# Override guide

Reference for editing `migration-plan.yaml` entries (T2 / I3).

| Case | Edit in plan |
|------|----------------|
| Platform integration (arango-like, cluster-shared, not passport) | `remoteRefPath: <cluster>`, `create: false` |
| Passport cred generated by EnvGene (rare) | `create: true` |
| Provider-generated cred (consul-bootstrap, k8s SA) | `create: false`, `writeToStore: false` (gap workaround; no `skip` yet) |
| Env-scoped biz cred, per-namespace granularity | `remoteRefPath: <cluster>/<env>/<ns>` |
| Multi-platform on cluster (two DBaaS instances) | `remoteRefPath: <cluster>/<scope>` — scope chosen by author |
| Biz cred pre-set by ops (Store already seeded) | `create: false`, `writeToStore: false` |
| System already seeded in Store | `create: false`, `writeToStore: false`, keep `remoteRefPath: global` |
| Same cred-id in passport and shared | Keep one authoritative source; drop or `writeToStore: false` on the other |

Template plans use Jinja `remoteRefPath` strings, not literal `<cluster>/...`
paths. Same intent: passport-shape vs env-shape vs operator override.

`remoteRefPath` is a prefix only. EnvGene appends the normalised cred-id when
composing the final Store path. Non-Jinja paths use **no leading `/`**.
