## Описание

PLACE-9 (SHOULD) проверяет количество используемых Cloud Passport, неоднозначность разрешения и размещение паспортов/credentials. Кластер-потребитель может использовать не больше одного основного и одного infra-паспорта. Роль infra определяется точным stem `passport-infra`; все остальные имена относятся к основным паспортам. Это не проверка имён NAME-8/9.

Участвуют только явно подключённые или автоматически используемые входы. Неоднозначная ссылка считается попыткой подключения, хотя для проверок содержимого паспорт выбрать нельзя. Размещение паспорта вне уровня кластера по-прежнему проверяет PLACE-3.

## Входные параметры

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Назначение |
| --- | --- | --- | --- | --- | --- |
| `index` | Обнаружение репозитория | Да | Нет | `RepoIndex` | Кластеры, окружения, записи паспортов и привязки |
| `connections` | Движок / общий отбор | Нет | Вычисляется, если не передан | `Connections` | Успешно выбранные паспорта окружений |
| `inventory.cloudPassport` | Определение окружения | Нет | Автоматическое разрешение | Точный stem паспорта | Имя для явного поиска |
| Слоты credentials паспорта | Файлы рядом с выбранным паспортом | Нет | При отсутствии замечания нет | `credentials/<stem>.yml`, затем `<stem>-creds.yml` | Первый существующий вход credentials, используемый локальным генератором |

## Ход обработки

1. **Собрать кандидатов разрешения паспорта**

   1. Для явной ссылки собрать совпадающие имена из Inventory окружения, его кластера и корневого `environments/`, в каталогах `cloud-passport/` и `cloud-passports/`.
   2. Для автоматического выбора сначала искать паспорт с именем кластера, затем `passport`, используя существующий автоматический поиск. Остановиться на первом непустом наборе совпадений; запасное имя не добавлять к найденному.
   3. Считать `.yml` и `.yaml` разными файлами, если они не ведут к одному физическому пути. Исключить пути вне репозитория и внутри `.git`. Посторонние имена и записи credentials не учитывать.

2. **Сообщить о неоднозначном разрешении**

   1. Если используемая ссылка или автоматический поиск дали больше одного физического кандидата, создать замечание о конфликте разрешения.
   2. Одинаковые наборы кандидатов объединить между окружениями: один общий конфликт — одно замечание.
   3. Включить все паспорта на позиции `1:1` и позиции ссылок в определениях затронутых окружений. Для автоматического выбора использовать `1:1` определения.
   4. Не включать неоднозначные группы в подсчёт успешно выбранных паспортов.

3. **Посчитать выбранные паспорта по кластеру-потребителю и роли**

   1. Сгруппировать однозначно выбранные физические файлы по кластеру окружения и роли основной/infra.
   2. Повторное использование одного файла несколькими окружениями считать один раз.
   3. При нескольких физических файлах одной роли выдать одно замечание со всеми этими паспортами. Сочетание одного основного и одного infra допустимо.

4. **Проверить каталог паспорта**

   1. Для выбранного паспорта, уже расположенного на уровне кластера, требовать путь внутри канонического `cloud-passport/` этого кластера. Вложенные каталоги допустимы.
   2. Выдать замечание для неканонического каталога кластера, например `cloud-passports/`.
   3. Размещение паспорта на уровне repository/environment оставить PLACE-3; не повторять его замечание в PLACE-9.

5. **Проверить используемый файл credentials**

   1. Для каждого однозначно выбранного паспорта сначала искать `credentials/<stem-паспорта>.yml` относительно каталога паспорта, затем соседний `<stem-паспорта>-creds.yml`. Первый существующий файл занимает слот входа. Если он ведёт вне репозитория или внутрь `.git`, пропустить проверку credentials, не выбирая следующий слот.
   2. Требовать, чтобы используемый файл credentials находился рядом с паспортом и внутри `cloud-passport/` кластера-владельца. Выбранный файл в подкаталоге credentials нарушает требование соседства, даже если рядом также есть неиспользуемая копия.
   3. Выдать одно замечание на неправильно размещённый физический файл credentials, сохранив позицию связанного паспорта. Содержимое credentials не читать и не проверять.

6. **Вернуть замечания**

   Вернуть Warning / Fix с сортировкой по пути, ключу и строке. Конфликт разрешения, превышение количества паспортов роли и размещение credentials — отдельные виды замечаний.

## Результат

PLACE-9 возвращает предупреждения с конкретными позициями и подсказками; файлы не переименовываются, не перемещаются и не удаляются. Описание каталога — `One Cloud Passport per cluster`. Консоль всегда выводит все тринадцать заголовков каталога: PLACE-9 расположен после PLACE-8 и перед PLACE-10, а блок PLACE-9 без замечаний содержит `No findings`. HTML-отчёт сохраняет существующее поведение и создаёт секции только для правил с замечаниями: секция PLACE-9 появляется лишь при наличии замечаний и располагается после PLACE-8 и перед PLACE-10, если эти секции присутствуют. Замечания сохраняют код CLI `0`.

## Обработка ошибок

**1a.** Отсутствующие ссылки, ненайденные паспорта и неиспользуемые файлы не дают замечаний PLACE-9. Использование определяется только найденными окружениями.

**2a.** Неоднозначность определяется по структурированным кандидатам, а не разбором текста заметок разрешения. Существующие заметки о пропуске могут возвращаться отдельно.

**2b.** Если определение окружения нельзя прочитать для точной позиции ссылки, использовать `1:1` этого файла; известный конфликт паспортов остаётся проверяемым.

**3a / 4a.** Ошибочный YAML выбранного паспорта не скрывает проблему количества или размещения: для этих проверок нужны путь и идентичность, а не содержимое.

**5a.** Отсутствующие credentials и невыбранные копии меньшего приоритета пропускаются. Локальный генератор проверяет указанные слоты `.yml`; использование соседнего `.yaml` либо произвольного похожего имени не предполагается.

**5b.** Файлы вне репозитория и внутри `.git` не входят в кандидаты. Внешние файлы и значения секретов не исследуются.

## Пример

Допустимо: бизнес-окружение автоматически выбирает `passport.yml`, infra-окружение явно указывает `passport-infra`:

```text
environments/c/cloud-passport/passport.yml
environments/c/cloud-passport/passport-creds.yml
environments/c/cloud-passport/passport-infra.yml
environments/c/cloud-passport/passport-infra-creds.yml
```

Если два окружения выбирают `business-a` и `business-b` из каталога паспортов кластера, выдаётся одно замечание о нескольких основных паспортах. Неподключённый `backup.yml` на подсчёт не влияет.

Если явная ссылка `cloudPassport: passport` совпадает с `environments/cloud-passport/passport.yml` и `environments/c/cloud-passport/passport.yml`, PLACE-9 сообщает о конфликте кандидатов. Паспорта не сливаются.

Если под каталогом выбранного паспорта существует `credentials/passport.yml`, локальный генератор выбирает его раньше `passport-creds.yml`; PLACE-9 сообщает о неправильном размещении используемого файла в подкаталоге.
