# Подключённые сущности

Английская версия: [../connections.md](../connections.md).
Спецификация: [общая область проверки](../../superpowers/specs/2026-09-11-connected-only-design.md).

## Отбор

Все правила проверяют только объекты с видимой локальной привязкой
или известным использованием генератором. NAME-3 также проверяет используемые
определения окружений и их каталоги кластеров/окружений; отбор namespace описан
в [name3.md](name3.md). Неподключённый файл не участвует в замечаниях, сравнении
значений, списке позиций, объединении категорий и каталоге ключей passport.
Discovery может индексировать его и сообщать об ошибке чтения как о пропуске.
Отдельного правила для отсутствующих ссылок не добавляется.

| Сущность | Подтверждение использования |
| --- | --- |
| ParameterSet | физический файл, оставшийся после `resolve_reference(index, env, reference)` для локальной deploy/e2e/technical-привязки |
| Cloud Passport | существующее разрешение `inventory.cloudPassport` или автоматический выбор passport кластера |
| Resource Profile Override | `envSpecificResourceProfiles` с существующим порядком уровней и каталогов |
| Общие credentials | `sharedMasterCredentialFiles` с существующим порядком уровней и каталогов |
| Credentials генерации Inventory | точный путь `Inventory/credentials/inventory_generation_creds.yml` найденного окружения |
| Shared Template Variables | `envTemplate.sharedTemplateVariables`, поиск локального генератора описан в [PLACE-10](place10.md) |
| Artifact Definition | `envTemplate.artifact`, `envTemplate.bgNsArtifacts.origin` или `.peer` выбирает `configuration/artifact_definitions/<application>.yml`, затем `.yaml` |
| Application / Registry Definition | пропускаются: текущие локальные входы не доказывают выбор определения используемым Solution Descriptor |

Идентичность определяется физическим путём. Для каждого использования сохраняются
окружение, цель, ссылка и категория. Совпадение имени в другом кластере не делает
файл подключённым. Нечитаемый выбранный файл занимает своё место в приоритетах,
но проверки содержимого его пропускают. Jinja и внешние привязки из шаблонов или
runtime не вычисляются и не предполагаются.

## Проекции ParameterSet и имена

Сначала разрешаются входы по всем уровням. Файл кластера с тем же именем при
подготовке заменяет файл репозитория. Для `full`, `lower` и `site` уже выбранные
входы ограничиваются нужными уровнями перед слиянием. Проекция не возвращает
затенённый файл, который окружение не использует.

NAME-1 и NAME-2 проверяют только выбранные файлы. NAME-4 объединяет категории
по физическому файлу и учитывает имена кластеров/окружений только из его реальных
использований. Разные физические файлы с одинаковым stem не влияют на требования
друг к другу. PLACE-6 пропускает цель без разрешившихся ParameterSet. PLACE-7
пропускает неразрешившиеся ссылки, сохраняя исходные позиции остальных элементов.
Тексты замечаний для подключённых сущностей сохраняются.

Каталоги passport содержат статическую таблицу контракта и ключи только выбранных
паспортов. Неиспользуемый паспорт кластера не подавляет PLACE-1 своими ключами.
PLACE-3 проверяет размещение выбранных паспортов. PLACE-4 проверяет выбранные
ParameterSet и не пытается читать неотрендеренный Jinja как обычный YAML.

## Artifact Definition и ограничения

Селектор — строка с непустыми первыми двумя частями, разделёнными двоеточием
(`application:version`). Как у генератора, последующие части не меняют имя
приложения. Значения с признаками шаблонов, неправильные контейнеры, старый GAV
в `templateArtifact` и неизвестные runtime-переопределения пропускаются.
Выбор идёт по имени файла, а не полю `name`. После выбора NAME-2 сравнивает `name`
с именем выбранного файла. Нечитаемый `.yml` всё равно приоритетнее `.yaml`.
Встроенный объект `registry` артефакта не является ссылкой на RegDef.

Для AppDefs/RegDefs нужен отдельно подтверждённый выбор приложения, например
поддержанный сценарий Solution Descriptor. Наличие каталога, накопленных
сгенерированных копий и внутреннее поле `name` не доказывают использование.
Сейчас правила пропускают эти записи.

## PLACE-8 и отчёт

PLACE-8 сохраняет Information / Review для известных пустых подключённых или
используемых файлов. Неподключённые, непустые, нечитаемые и неизвестные структуры
замечаний не дают. Отсутствие credentials по фиксированному пути допустимо:
генератор использует значение по умолчанию. Разрешение алиасов и неоднозначных
совпадений первого каталога сохраняет существующее поведение PLACE-8.
PLACE-10 добавляет тринадцатый заголовок каталога после PLACE-9 и перед NAME-1.
Новых опций CLI, других изменений уровней серьёзности, автоисправлений и сети нет.

## Примеры

Неподключённый `parameters/unused.yml` не проверяется, даже если его имя неверно
или ключи могли бы вызвать NAME-1/2 либо PLACE-4. Привязка к точному stem включает
физический файл в область соответствующих проверок.

Если `service-deploy.yml` используется как deploy в одном кластере и как e2e
в другом, NAME-4 сообщает о суффиксе только второго файла. Неразрешившаяся e2e-ссылка
в другом кластере не меняет категорию первого файла.

Синтетические примеры: `.venv/bin/envgene-linter check testdata/place8/not-ok`
и `testdata/place8/ok`. Три подключённых пустых файла дают три замечания PLACE-8;
три неподключённых пустых файла не дают ни одного.

## Конфликты разрешения паспорта

[PLACE-9](place9.md) также проверяет неоднозначных кандидатов по используемой ссылке паспорта или автоматическому поиску. Для остальных проверок содержимого такие кандидаты не считаются выбранными. Правило также проверяет первый существующий известный файл credentials паспорта, не читая содержимое. Отсутствующие и неиспользуемые файлы по-прежнему пропускаются.

## Shared Template Variables

Явные привязки `envTemplate.sharedTemplateVariables` выбирают файлы переменных по поиску локального генератора. Их физические пути входят в общий отбор и отбор окружения. [PLACE-10](place10.md) проверяет каталог их типа, а также каталоги ParameterSet, профилей, shared credentials и паспортов. Тип произвольного YAML по содержимому не предполагается.
