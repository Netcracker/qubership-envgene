## Описание

NAME-3 проверяет kebab-case в именах подключённых файлов, каталогов кластеров
и окружений, а также используемых namespace. Поля YAML и значения enum не входят
в область проверки. Все замечания — Information / Review; имена не изменяются.

## Входные параметры

Это входы `check(index, connections=None)`, а не дополнительные параметры CLI.

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Влияние |
| --- | --- | --- | --- | --- | --- |
| `index` | Аргумент правила из обнаружения репозитория | Да | Нет | `RepoIndex.root`, кластеры/окружения, записи Resource Profile и привязки | Даёт границу репозитория, используемые каталоги и разрешение профилей |
| `connections` | Необязательный аргумент / общий отбор | Нет | `compute_connections(index)` | `Connections.selected_paths`, `parameter_files`, `parameter_uses` | Даёт выбранные пути, написание выбранных ParameterSet и цели namespace |

## Ход обработки

1. **Собрать подключённые пути и цели привязок**

   1. Использовать `connections`, а при отсутствии вычислить его из `index`.
   2. Создать отображение по физическому пути из `connections.selected_paths`.
      Для ParameterSet заменить отображаемый путь путём выбранной записи из
      `parameter_files`. Неподключённый алиас не заменяет выбранное написание.
   3. Собрать цели из `parameter_uses` отдельно для каждого окружения.
      Учитываются только разрешившиеся использования ParameterSet.

2. **Проверить используемые каталоги и определения окружений**

   1. Обойти индексированные кластеры хотя бы с одним найденным окружением.
      Проверить имя кластера как `Cluster directory`, имя каждого окружения —
      как `Environment directory`, включая окружения с нечитаемыми определениями.
   2. Добавить каждый существующий `Inventory/env_definition.yml` в отображение
      файлов по физическому пути, сохранив написание пути определения.
   3. Добавить цели Resource Profile только при разрешении привязки через
      `resolve_named_reference` в этом окружении, с общим приоритетом профилей.
   4. Для каждой собранной цели проверять namespace, только если это существующий
      непосредственный подкаталог `Namespaces/` данного окружения, его имя точно
      равно цели, а разрешённый физический путь остаётся внутри репозитория.
      Исключить `.` и `..`, а также `cloud` без учёта регистра. Тип — `Namespace`.
   5. Для всех типов каталогов пропускать пути с `.git` и точные имена из списка
      служебных каталогов: `Inventory`, `Namespaces`, `parameters`, `credentials`,
      `Credentials`, `resource_profiles`, `rp_override`, `Profiles`,
      `configuration`, `configurations`, `shared-template-variables`,
      `shared_template_variables`, `cloud-passport`, `cloud-passports`,
      `app-deployer`, `cloud-deployer`.

3. **Проверить выбранные имена файлов**

   1. Обойти дедуплицированное отображение файлов по пути. Оставить пути,
      лексически находящиеся под `index.root/environments`, разрешающиеся внутри
      `index.root` и не содержащие компонента `.git` ниже `environments/`.
   2. Допустить суффиксы `.yml`, `.yaml`, `.json`, `.yml.j2`, `.yaml.j2`, `.json.j2`.
      Сам суффикс не доказывает использование.
   3. Получить стем через `paramset_stem` (снять `.j2`, затем расширение данных)
      и проверить как `File`. Используемые скрытые имена не исключаются.
      Исключения нет и для входов генератора: `env_definition.yml` и выбранного
      `inventory_generation_creds.yml`.

4. **Проверить имена и вернуть замечания**

   1. Потребовать полного совпадения с `^[a-z0-9]+(?:-[a-z0-9]+)*$` для каждого
      имени, выбранного в шагах 2 и 3.
   2. Для каждого несовпавшего имени создать одно замечание по его пути на `1:1`.
   3. Отсортировать замечания по пути, ключу и строке.

## Результат

Результат — список замечаний `NAME-3` с `severity=information`,
`issue_type=Information`, `action=Review`, неверным именем в `key`,
типом объекта в `scope`, одной позицией и пустым `related`.

- Сообщение: `{kind} {name!r} is not kebab-case.` Написание типа берётся точно
  из хода обработки.
- Подсказка: `Review whether this name can be kebab-case. Do not rename it if generation or other logic still depends on the current spelling.`
- Описание в каталоге: `Filenames, directories, and namespaces use kebab-case`.

Тексты диагностики остаются английскими. Консоль выводит позицию, уровень,
сообщение и подсказку; HTML — позицию и метки Information / Review. Пустой блок
состоит из `NAME-3` и следующей строки `No findings`; обычное найденное окружение
даёт замечание, поскольку стем `env_definition` содержит подчёркивание.

## Обработка ошибок

**1a.** Неподключённые и затенённые файлы не добавляют имён. Неиспользуемые
кластеры и каталоги namespace пропускаются, даже если не соответствуют regex.

**2a.** Пустая или неразрешившаяся привязка не доказывает использование namespace.
Наличие сгенерированного каталога и неизвестные входы шаблона также недостаточны.

**2b.** Нечитаемое определение не мешает проверке уже найденного окружения,
его кластера и имени файла определения.

**3a.** Пути вне допустимого поддерева, выходящие за репозиторий, внутри `.git`
или с другими суффиксами пропускаются. NAME-3 проверяет имена и не требует
успешного разбора содержимого выбранного файла.

## Пример

Пусть найдено окружение `environments/Cluster_01/Env_01` с
`Inventory/env_definition.yml`. Разрешившаяся привязка ParameterSet к цели `Foo`
выбирает `Inventory/parameters/Cloud_Deploy.yml`. Каталог `Namespaces/Foo`
существует, других выбранных файлов нет.

Правило создаёт пять замечаний Information / Review:

| Тип | Ключ |
| --- | --- |
| Cluster directory | `Cluster_01` |
| Environment directory | `Env_01` |
| File | `env_definition` |
| File | `Cloud_Deploy` |
| Namespace | `Foo` |

Без разрешившейся привязки ParameterSet или профиля к `Foo` замечание по namespace
исчезает. Отдельный неиспользуемый каталог `Cluster_01` и неподключённый
`Cloud_Deploy.yml` замечаний не дают.
