## Описание

NAME-4 проверяет, что стем привязанного ParameterSet имеет вид
`<subject>-<category>` и не содержит имя кластера/окружения из его реальных
использований, номер задачи или маркер релиза. Все замечания — Information /
Review. Правило читает выбранные стемы и привязки без слияния Effective Set
и изменения файлов.

## Входные параметры

Это входы `check(index, connections=None)`, а не дополнительные параметры CLI.

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Влияние |
| --- | --- | --- | --- | --- | --- |
| `index` | Аргумент правила из обнаружения репозитория | Да | Нет | `RepoIndex` с ParameterSet и привязками окружений | Даёт данные для общего разрешения подключений |
| `connections` | Необязательный аргумент / общий отбор | Нет | `compute_connections(index)` | `Connections.parameter_files` и `parameter_uses` | Даёт выбранные стемы, категории и реальные использующие кластеры/окружения |

## Ход обработки

1. **Выбрать файлы и их реальные использования**

   1. Использовать `connections`, а при отсутствии вычислить его из `index`.
   2. Обойти `connections.parameter_uses` по физическому пути и найти
      соответствующую запись в `parameter_files`. Если её нет, пропустить вход.
   3. Использовать стем и путь выбранной записи. Дедуплицировать физические
      алиасы; посторонний файл с тем же стемом и неподключённый алиас не участвуют.
   4. Собрать категории использований этого файла, а имена кластеров/окружений
      получить разделением `environment` каждого использования по первому `/`.

2. **Определить требуемые токены категории**

   1. Сопоставить deploy (`envSpecificParamsets`) с `deploy`, e2e
      (`envSpecificE2EParamsets`) с `pipeline`, technical
      (`envSpecificTechnicalParamsets`) с `technical`.
   2. Сформировать `scope` из различных требуемых токенов по алфавиту через `, `.
      Выбранный в нескольких категориях файл должен удовлетворять всем.

3. **Исключить встроенные имена областей, задач и релизов**

   1. Искать regex задачи `(?:^|-)(?:ticket|jira|issue)-\d+` без учёта регистра
      и regex релиза `(?:^|-)(?:r\d+(?:-\d+)?|20\d{2}[.-]\d{1,2})` с учётом
      регистра. Это поиск подстроки без требования границы после маркера.
   2. Сравнить каждое непустое реальное имя кластера/окружения без учёта регистра
      со всем стемом либо его префиксом, инфиксом или суффиксом по границам дефиса.
      Слова `env`, `cluster` и `site` сами по себе не запрещены.
   3. При совпадении создать сообщение об области/задаче и перейти к следующему
      файлу. Эта ветка имеет приоритет перед проверкой окончания категории.

4. **Проверить предметную часть и окончание категории**

   1. Разделить стем по `-`. Потребовать хотя бы два токена и непустое значение
      каждого токена до последнего.
   2. Потребовать точного равенства множества нужных токенов категории множеству
      из последнего токена, с учётом регистра. После окончания ничего быть не
      должно. Несколько различных категорий один стем удовлетворить не может.
   3. При нарушении создать сообщение об окончании, перечислив требуемые токены
      по алфавиту через `/`. Иначе ничего не создавать. Отдельной проверки
      kebab-case на этом шаге нет.

5. **Вернуть упорядоченные замечания**

   1. Создать не более одного замечания на выбранный физический файл: путь
      выбранной записи, позиция `1:1`, стем в `key`, одна позиция и пустой `related`.
   2. Отсортировать по пути, ключу и строке.

## Результат

Результат — список замечаний `NAME-4` с `severity=information`,
`issue_type=Information` и `action=Review`.

- Сообщение об области/задаче: `ParameterSet {stem!r} bakes a cluster, environment, ticket or release into the name.`
- Сообщение об окончании: `ParameterSet {stem!r} must end with -{token} to match its env_definition binding ({scope}).`
- Общая подсказка: `Review whether this stem can be <subject>-<category>. Do not rename it if env_definition or other logic still depends on the current spelling.`
- Описание в каталоге: `Bound ParameterSet stem is <subject>-<category>`.

Тексты диагностики остаются английскими. Консоль выводит позицию, уровень,
сообщение и подсказку; HTML — позицию и метки Information / Review.
Пустой блок состоит из `NAME-4` и следующей строки `No findings`.

## Обработка ошибок

**1a.** Неразрешившиеся привязки и неотрендеренный Jinja не входят в общий отбор
ParameterSet. Они не добавляют требований к категориям или владельцам другого файла.

**1b.** Отсутствующая выбранная запись пропускается. Стем выбранной записи с ошибкой
загрузки YAML всё равно может проверяться: NAME-4 не читает её содержимое.

**4a.** Отсутствие предметной части (`deploy`, `-deploy`, `a--deploy`), неверное
окончание или конфликт категорий дают сообщение об окончании. Автоматического
переименования и изменения `env_definition` нет.

## Пример

Пусть файлы ниже выбраны привязками, а их предметные части не совпадают
с реальными именами кластеров или окружений:

| Выбранный стем | Категория привязки | Результат NAME-4 |
| --- | --- | --- |
| `bss` | deploy | Одно замечание об окончании; `scope=deploy` |
| `bss-deploy` | deploy | Нет замечания |
| `postgresql-pipeline` | e2e | Нет замечания |
| `-deploy` | deploy | Одно замечание: пустая предметная часть |
| `postgresql-deploy-ha` | deploy | Одно замечание: последний токен `ha` |
| `bss-deploy` (один физический файл) | deploy и e2e | Одно замечание; токен `deploy/pipeline`, scope `deploy, pipeline` |
| `jira-123-bss-deploy` | deploy | Одно замечание об области/задаче |

Для `bss` точный текст сообщения:

```text
ParameterSet 'bss' must end with -deploy to match its env_definition binding (deploy).
```

Неподключённый `extra.yml` не даёт замечания. У двух разных физических файлов
`bss-deploy.yml` категории и владельцы независимы: использование одного в e2e
не влияет на другой.
