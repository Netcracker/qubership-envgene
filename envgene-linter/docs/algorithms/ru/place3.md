## Описание

PLACE-3 проверяет размещение выбранных файлов Cloud Passport. Паспорт должен находиться на уровне кластера. Текущая реализация проверяет только размещение файлов; ключи Cloud Passport внутри ParameterSet проверяет PLACE-4.

## Входные параметры

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Назначение |
| --- | --- | --- | --- | --- | --- |
| `index` | Обнаружение репозитория | Да | Нет | `RepoIndex` с паспортами | Пути файлов и уровень владельца |
| `connections` | Общий отбор подключений | Нет | Вычисляется, если не передан | `Connections.passports` | Явно подключённые или автоматически выбранные паспорта |
| `full`, `lower`, `site`, `catalogs` | Движок | Да в текущей сигнатуре | Нет | Проекции Effective Set / каталоги passport | Входы для совместимости; правило их не использует |

## Ход обработки

1. **Выбрать используемые паспорта**

   Использовать общий индекс подключений движка или вычислить его при прямом вызове. Выбор основан на `inventory.cloudPassport` либо существующем автоматическом разрешении паспорта кластера.

2. **Проверить уровень каждого паспорта в индексе**

   1. Сопоставить физический путь с множеством выбранных паспортов. Неподключённый файл пропустить.
   2. Паспорт с владельцем-кластером и без владельца-окружения уже размещён на уровне cluster: пропустить его.
   3. Для остальных выбранных паспортов создать замечание на позиции `1:1`. Читаемое содержимое YAML для проверки размещения не требуется.

3. **Определить рекомендуемый каталог**

   1. Если у паспорта известен кластер, предложить `environments/<cluster>/cloud-passport/`.
   2. Иначе, если индекс содержит ровно один кластер, предложить каталог этого кластера.
   3. Иначе предложить `cloud-passport/` некоторого кластера без выбора конкретного владельца.

4. **Вернуть замечания о размещении**

   Ключ — stem паспорта; область — его кластер либо `repository`. Порядок замечаний соответствует порядку паспортов в индексе.

## Результат

Выбранный паспорт вне уровня cluster даёт Warning / Fix с сообщением `Passport <stem> is not at the cluster layer.` Подсказка указывает каталог из шага 3. Проверки отдельных ключей, слияния и перемещения файлов не выполняются. Пустой результат отображается как `No findings`; замечания сохраняют код CLI `0`.

## Обработка ошибок

**1a.** Отсутствующая или неоднозначная ссылка может оставить окружение без выбранного паспорта; сообщения разрешения выводятся отдельно. PLACE-3 не создаёт замечания об отсутствующем файле.

**2a.** Неподключённые паспорта пропускаются даже при неправильном размещении.

**2b.** Нечитаемый YAML или Jinja не отменяют проверку размещения, если паспорт выбран: расположение файла известно. Это не означает рендеринг или проверку содержимого.

## Пример

Окружение указывает `inventory.cloudPassport: cp`. Выбран файл:

```text
environments/c/e/Inventory/cloud-passport/cp.yml
```

PLACE-3 выдаёт одно Warning / Fix на `cp.yml:1:1` и предлагает `environments/c/cloud-passport/`.

Выбранный `environments/c/cloud-passport/cp.yml` размещён правильно и замечания не даёт. Неиспользуемый паспорт внутри окружения также не даёт замечания: он не входит в отбор.
