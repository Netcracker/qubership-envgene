## Описание

PLACE-1 находит одинаковые значения параметров, независимо заданные минимум двумя участвующими окружениями или кластерами, и предлагает перенести их на общий уровень. Повтор уже существующего значения нижележащей проекции обрабатывает PLACE-2. Участвуют только разрешённые подключённые ParameterSet; уровня шаблона нет.

## Входные параметры

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Назначение |
| --- | --- | --- | --- | --- | --- |
| `index` | Обнаружение репозитория | Да | Нет | `RepoIndex` | Кластеры и найденные окружения |
| `full` | Effective Set | Да | Нет | Окружение → области → значения | Входы repository + cluster + environment |
| `lower` | Effective Set | Да | Нет | Та же структура | Входы repository + cluster |
| `site` | Effective Set | Да | Нет | Та же структура | Только входы repository |
| `catalogs` | Каталоги Cloud Passport | Нет | `None` | Окружение/кластер → множество верхнеуровневых ключей | Исключает ключи контракта passport; движок передаёт каталоги |
| Порог согласия | Константа правила | Фиксирован | `2` | Минимум два участника | Число участников в области; не параметр CLI |

## Ход обработки

1. **Подготовить проекции подключённых входов**

   1. Движок разрешает реальные входы ParameterSet, затем фильтрует их для `full`, `lower`, `site`. Затенённый файл не возвращается в проекцию.
   2. Для каждого конечного значения сохраняются уровень происхождения, файл, ссылка и позиция YAML. Область сравнения — цель × категория, при наличии также приложение.

2. **Собрать вклад окружений внутри кластера**

   1. Обработать окружения по имени. Пропустить окружение, если отсутствует `full` или `lower`.
   2. Оставить значения `full`, заданные на уровне environment.
   3. Если переданы каталоги, исключить значения с верхнеуровневым ключом из каталога passport окружения.
   4. Сравнить ту же область и путь ключа с `lower`. Существующее равное значение означает повтор: исключить его. Отсутствующее или другое значение означает самостоятельный вклад окружения.

3. **Найти общее значение окружений**

   1. Участниками области считать только окружения, у которых остался хотя бы один вклад в неё. Остальные окружения не поддерживают и не блокируют совпадение.
   2. Требовать минимум двух участников. Взять пересечение путей ключей: каждый участник должен содержать проверяемый путь.
   3. Если значения всех участников равны, выдать одно замечание с предложением переноса на уровень cluster.

4. **Собрать вклад кластеров**

   1. Пропустить кластеры без окружений. В остальных обработать окружения по имени.
   2. Повторить шаг 2 для `lower` и `site`, оставляя значения уровня cluster и исключая ключи каталога passport кластера.
   3. Для пары область/путь сохранить первый вклад. Если другое окружение того же кластера видит другое значение этой пары на уровне cluster, отметить конфликт.
   4. После обработки кластера удалить все конфликтующие пути и пустые области.

5. **Найти общее значение кластеров**

   Применить шаг 3 к вкладам кластеров: минимум два участвующих кластера должны содержать путь и иметь равные значения. Выдать замечание с предложением переноса на уровень repository.

6. **Сформировать замечания и позиции**

   1. Основной файл, строку и столбец взять из первого участника; ключ — путь конечного значения через точку.
   2. Добавить позиции всех владельцев, убрав дубли по файлу/строке/столбцу, и сведения об источнике каждого владельца.
   3. Вернуть сначала замечания environment → cluster, затем cluster → repository. Области и общие пути обрабатываются в сортированном порядке.

## Результат

На каждое общее значение формируется Warning / Fix. Область — `<cluster> <scope>` или `repository <scope>`. Сообщение указывает ключ и число согласных окружений/кластеров; подсказка — общий уровень и удаление отдельных копий. Файлы не изменяются. Без совпадений возвращается пустой список, CLI печатает `No findings`. Наличие замечаний сохраняет код завершения `0`.

## Обработка ошибок

**1a.** Неразрешившиеся ссылки и неотрендеренный Jinja не дают значений Effective Set; нечитаемый YAML отмечается отдельно как пропущенный вход.

**2a / 4a.** Отсутствующая проекция исключает окружение из соответствующего сравнения. Ключи passport и повторы пропускаются штатно.

**3a / 5a.** Недостаточно участников, нет общего пути либо значения различаются — замечания нет. Согласия большинства недостаточно.

**4b.** Разногласие внутри кластера удаляет путь из его вклада, не останавливая правило.

## Пример

Два окружения подключают `env-deploy` через `envSpecificParamsets.cloud`. У каждого свой `Inventory/parameters/env-deploy.yml`:

```yaml
name: env-deploy
parameters:
  LOG_LEVEL: info
```

Подключённого значения `LOG_LEVEL` в нижележащих проекциях нет. Оба окружения вносят одинаковое значение: одно замечание предлагает перенос в `environments/<cluster>/parameters/`.

Если оба также подключают кластерный файл с `LOG_LEVEL: info`, локальные значения становятся повторами: PLACE-1 молчит, их проверяет PLACE-2. Третье окружение без вклада в эту область не мешает первому примеру. Третий участник, внесший другой ключ, но не `LOG_LEVEL`, блокирует совпадение.
