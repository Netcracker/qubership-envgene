## Описание

NAME-1 выявляет разные имена параметров с точно совпадающими непустыми
строковыми значениями в подключённых ParameterSet. Совпадение — повод для
проверки, а не доказательство алиаса. Все замечания имеют тип Information и
действие Review; файлы и ключи не изменяются. Правило читает выбранные записи
без слияния Effective Set.

## Входные параметры

Это входы `check(index, connections=None)`, а не дополнительные параметры CLI.

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Влияние |
| --- | --- | --- | --- | --- | --- |
| `index` | Аргумент правила из обнаружения репозитория | Да | Нет | `RepoIndex` с ParameterSet и привязками окружений | Даёт выбранный YAML и позиции ключей |
| `connections` | Необязательный аргумент / общий отбор | Нет | `compute_connections(index)` | `Connections.parameter_files` по физическому пути | Ограничивает группы значений выбранными ParameterSet |

## Ход обработки

1. **Выбрать записи ParameterSet**

   1. Использовать переданный `connections`, а при его отсутствии вызвать
      `compute_connections(index)`.
   2. Взять `connections.parameter_files`: выбранные файлы уровня репозитория,
      кластера и окружения с дедупликацией по физическому пути. Сохранить имя и
      путь выбранной записи; неподключённый алиас не подменяет их.
   3. Пропустить Jinja, записи с `error` и записи с `loaded is None`.
      Другие типы YAML, неподключённые и затенённые файлы не участвуют.

2. **Собрать именованные строковые листья**

   1. Обойти вложенные отображения `parameters` на любой глубине через
      `yamlio.leaves`. Сохранить только строки, отличные от `""`; внутрь списков
      не заходить. Числа, логические значения и null не участвуют.
   2. Использовать полный путь через точки как имя ключа. Поэтому
      `outer.KAFKA_URL` и `KAFKA_URL` — разные имена.
   3. Если `applications` — список, рассмотреть его элементы-отображения.
      Получить имя приложения как `entry.get("appName") or entry.get("name")`;
      потребовать истинность результата и тип отображения у `parameters`.
      Для каждого подходящего `applications[i].parameters` повторить сбор
      листьев, добавив к ключу полученное имя, преобразованное в строку, и `.`.
      Сохранить файл и YAML-позицию каждого вхождения.

3. **Сгруппировать значения и исключить пары учётных данных**

   1. Сгруппировать все вхождения по точному строковому значению между
      выбранными файлами.
   2. Собрать множество различных полных имён ключей в каждой группе.
   3. Сравнить последние сегменты пути без учёта регистра. Для сегмента с
      окончанием `_USER` или `_USERNAME` искать другое имя с тем же префиксом
      и окончанием `_PASSWORD` или `_PASS`. Родительские пути могут различаться.
   4. Одновременно исключить обе стороны каждой найденной пары. Оставить группу,
      только если в ней хотя бы два разных имени; повторений одного недостаточно.

4. **Сформировать и упорядочить замечания**

   1. Сохранить все вхождения оставшихся имён и отсортировать по пути, затем
      ключу. Первое вхождение задаёт основной путь, позицию и ключ.
   2. Создать одно замечание на оставшуюся группу значений. В `locations`
      включить все оставшиеся вхождения, в `related` — уникальные имена по алфавиту.
   3. Перед возвратом отсортировать замечания по пути, ключу и строке.

## Результат

Результат — список замечаний `NAME-1` с `severity=information`,
`issue_type=Information`, `action=Review` и `scope=repository`.

- Сообщение: `Keys {sorted names} share the value {value!r}.` Имена разделяются `, `.
- Подсказка: `Review whether they mean the same concept for the same consumer. Do not collapse them unless that is intended.`
- Описание в каталоге: `Different keys may name the same concept`.

Тексты диагностики остаются английскими. Консоль выводит все позиции, уровень,
сообщение и подсказку; HTML — все позиции и метки Information / Review.
Пустой блок состоит из `NAME-1` и следующей строки `No findings`.

## Обработка ошибок

**1a.** Отсутствующая или неразрешившаяся привязка не выбирает вход и не
создаёт замечание NAME-1. Обнаружение файлов может отдельно сообщить о пропуске
из-за ошибки чтения.

**1b.** Выбранный нечитаемый или неотрендеренный файл не даёт листьев.
Проверка остальных выбранных записей продолжается.

**3a.** Группа с менее чем двумя именами после исключения пар не даёт замечания.
Одного совпадения значений недостаточно для объединения ключей.

## Пример

Пусть привязка выбирает `cloud-deploy.yml` с содержимым:

```yaml
name: cloud-deploy
parameters:
  KAFKA_URL: kafka.internal:9092
  BOOTSTRAP_SERVERS: kafka.internal:9092
  STREAMING_BROKER_ADDRESS: kafka.internal:9092
```

Результат — одно замечание Information / Review, три позиции и имена в `related`
по алфавиту. Сообщение:

```text
Keys BOOTSTRAP_SERVERS, KAFKA_URL, STREAMING_BROKER_ADDRESS share the value 'kafka.internal:9092'.
```

Два выбранных файла только с `KAFKA_URL` и этим значением не дают замечания.
`POSTGRES_DBA_USER` и `POSTGRES_DBA_PASSWORD` с одним значением исключаются как
пара. Параметры приложения сравниваются как, например, `billing.KAFKA_URL`
и `billing.BOOTSTRAP_SERVERS`. Неподключённая копия не добавляет имён и позиций.
