## Описание

PLACE-4 (SHOULD) сообщает о ключах контракта Cloud Passport в подключённых
ParameterSet всех выбранных уровней. Правило предлагает перенести ключ в
соответствующий cloud-passport. Оно читает привязки и YAML, не вычисляет
эффективные значения и не изменяет файлы. Размещение файлов паспортов проверяет PLACE-3.

## Входные параметры

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Влияние |
| --- | --- | --- | --- | --- | --- |
| `index` | Discovery → `check` | Да | Нет | `RepoIndex` | Окружения, привязки и обнаруженные файлы |
| `connections` | Вызывающий код → `check` | Нет | `None`: `compute_connections(index)` | `Connections` | Выбранные физические файлы и их использования |
| `TABLE` | `passport.py` | Да | Встроенный каталог | Множество точных имён ключей контракта | Определяет запрещённые верхние ключи параметров |

## Ход обработки

1. **Выбрать подключённые ParameterSet**

   1. Использовать переданные `connections` или вычислить их из `index`.
   2. Перебрать `connections.parameter_files`, удаляя повторы по разрешённому физическому
      пути. Участвуют файлы репозитория, кластера и окружения, оставшиеся после общего
      разрешения привязок. Затенённые, непривязанные, посторонние одноимённые файлы
      и шаблоны Jinja исключены.

2. **Прочитать отображение параметров**

   1. Использовать загруженный YAML выбранного файла. При обычном discovery выбранные
      файлы уже содержат документ; файлы без него пропускаются.
   2. Проверить, что корень и корневое поле `parameters` — отображения.
      `applications[].parameters` не просматривается.

3. **Найти ключи контракта**

   1. Обойти `leaves(parameters)`: рекурсивно спускаться в отображения; списки и
      скалярные значения считать листьями. Пустое отображение листьев не содержит.
   2. Преобразовать первый компонент пути листа в строку и точно сопоставить с `TABLE`.
      Ключи фактических файлов паспортов не расширяют каталог.
   3. Сохранить каждый совпавший верхний ключ один раз на файл независимо от числа
      вложенных листьев.

4. **Сформировать замечания**

   1. Получить позицию через `LoadedYaml.position(("parameters", key))`.
   2. Создать одно замечание Warning / Fix на файл и ключ. Отсортировать по
      `(path.as_posix(), key, line)`.

## Результат

`check(index, connections=None)` возвращает список `Finding`: правило `PLACE-4`,
severity `warning`, тип `Warning`, действие `Fix`, `key` — ключ контракта.
Единственная позиция указывает на верхний ключ в ParameterSet; `related` пуст.
`scope` соответствует уровню файла: `repository`, `<cluster>` или `<cluster>/<env>`.

Сообщение: `{key} is a Cloud Passport contract key; do not store it in a ParameterSet.`

Подсказка: `Move {key} to the cluster cloud-passport, or to this environment's cloud-passport if the value is an override.`

Описание в каталоге: `Cloud Passport keys do not belong in ParameterSets`.
Консоль и HTML располагают правило после PLACE-3 и перед PLACE-6, включая пустой
блок. Сами эти предупреждения сохраняют код завершения 0. Файлы не изменяются.

## Обработка ошибок

**1a.** Ссылка без выбранного физического ParameterSet не добавляет файл для проверки.

**2a.** Отсутствующий или нечитаемый документ, корень или `parameters` другого типа
не дают замечания. Для вручную переданной записи Jinja вспомогательный метод
может повторно прочитать YAML и перехватывает `YamlReadError`; обычный общий
алгоритм исключает Jinja до этого шага и никогда не рендерит шаблоны.

**4a.** При отсутствии точной позиции `LoadedYaml.position` использует последнюю
доступную позицию предка; начальная позиция — строка 1, столбец 1.

## Пример

Пусть окружение ссылается на `shared`, а общий алгоритм выбирает
`environments/parameters/shared.yml`:

```yaml
parameters:
  CLOUD_API_HOST:
    internal: api.example.invalid
    external: public.example.invalid
  APP_MODE: demo
```

Результат — одно Warning / Fix для `CLOUD_API_HOST` на позиции верхнего ключа,
со scope `repository`. Два вложенных значения не создают два замечания.
Неподключённая копия файла замечаний не даёт. Значение `CLOUD_API_HOST: {}`
также не даёт замечания: у него нет листьев.
