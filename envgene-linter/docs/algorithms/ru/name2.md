## Описание

NAME-2 сравнивает стем имени подключённого файла с полем `name` в корне YAML.
Стем файла служит ключом ссылки. Несовпадение даёт Warning / Fix, отсутствующее
имя — Information / Review. Правило предлагает установить `name`, но не меняет
и не переименовывает файлы. Слияние Effective Set не требуется.

## Входные параметры

Это входы `check(index, connections=None)`, а не дополнительные параметры CLI.

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Влияние |
| --- | --- | --- | --- | --- | --- |
| `index` | Аргумент правила из обнаружения репозитория | Да | Нет | `RepoIndex` с ParameterSet, именованными сущностями и привязками | Даёт стемы файлов, корневой YAML и позиции ключей |
| `connections` | Необязательный аргумент / общий отбор | Нет | `compute_connections(index)` | `Connections.parameter_files` и `artifact_definitions` | Выбирает записи для сравнения |

## Ход обработки

1. **Выбрать подключённые файлы**

   1. Использовать `connections`, а при отсутствии вычислить его из `index`.
   2. Взять ParameterSet из `connections.parameter_files`, сохранив выбранные
      записи и дедуплицируя физические пути.
   3. Взять записи `index.named_entities`, чьи разрешённые физические пути есть
      в `connections.artifact_definitions`. Общий отбор разрешает буквальные
      ссылки `envTemplate.artifact`, `envTemplate.bgNsArtifacts.origin` и `.peer`
      по имени файла приложения, предпочитая `.yml` перед `.yaml`.
   4. Исключить неподключённые файлы и Application/Registry Definitions без
      доказанного локального использования. Пропустить Jinja, ошибки загрузки
      и записи без загруженного YAML.

2. **Прочитать объявленное имя**

   1. Использовать индексированный стем от `paramset_stem`: сначала снимается
      `.j2`, затем расширение данных.
   2. Читать `name` только из корневого отображения. Корень другого типа,
      отсутствующий ключ, null или `""` означают отсутствие имени.
   3. Остальные значения преобразовать через Python `str(value)`, без удаления
      пробелов и нормализации регистра. Например, число `1` становится `"1"`.

3. **Сравнить имена и сформировать замечание**

   1. При отсутствии имени создать Information / Review. Использовать позицию
      ключа `name`, если он есть, иначе `1:1`.
   2. Если преобразованное имя совпадает со стемом, ничего не создавать.
   3. Если имя отличается от стема, создать Warning / Fix на ключе `name`.
   4. Установить `kind=ParameterSet` или `kind=Artifact definition`, путь
      выбранной записи, `key=name`, `scope=stem`, одну позицию и пустой `related`.

4. **Вернуть упорядоченные замечания**

   1. Отсортировать по пути, ключу и строке. Каждая проверенная запись даёт
      не более одного замечания.

## Результат

Результат — список замечаний `NAME-2` с точными шаблонами диагностики:

| Случай | Уровень / тип / действие | Сообщение | Подсказка |
| --- | --- | --- | --- |
| Несовпадение | `warning` / Warning / Fix | `{kind} filename stem {stem!r} does not equal the name field {declared!r}.` | `Set name: {stem} to match the filename, which is the reference key.` |
| Нет имени | `information` / Information / Review | `{kind} {filename} has no name field; EnvGene requires it to equal the filename stem {stem!r}.` | `Set name: {stem}` |

`filename` — имя файла с расширением. Описание в каталоге:
`Filename stem must equal the name field`. Тексты диагностики остаются английскими.
Консоль выводит позицию, уровень, сообщение и подсказку; HTML — позицию и тип/действие
замечания. Пустой блок состоит из `NAME-2` и следующей строки `No findings`.

## Обработка ошибок

**1a.** Неразрешившиеся ссылки и недоказанный выбор во время выполнения не дают
замечаний NAME-2; обнаружение файлов может отдельно сообщить об ошибках чтения.

**1b.** Выбранный некорректный `.yml` Artifact Definition сохраняет приоритет
над `.yaml`, но пропускается из-за ошибки загрузки. NAME-2 не переходит к файлу
с меньшим приоритетом.

**2a.** Отсутствующее, пустое или null-имя обрабатывается шагом 3.1, а не как
несовпадение. Успешно загруженный корень другого типа также попадает в эту ветку.

## Пример

Пусть привязка выбирает `cloud-deploy.yml`:

```yaml
name: deploy-params
parameters: {}
```

Одно замечание Warning / Fix указывает на `name`, имеет `scope=cloud-deploy`
и текст:

```text
ParameterSet filename stem 'cloud-deploy' does not equal the name field 'deploy-params'.
Set name: cloud-deploy to match the filename, which is the reference key.
```

`name: cloud-deploy` устраняет замечание. Удаление `name`, null или `""` дают
одно Information / Review с подсказкой `Set name: cloud-deploy`.
Неподключённая копия или Jinja-файл замечаний не дают.
