## Описание

PLACE-7 (SHOULD) требует одну категорию на подключённое имя ссылки ParameterSet
в окружении. Категория определяется полем привязки в `env_definition.yml`.
Повтор ссылки внутри одной категории допустим, в том числе под разными целями.
Категории разных окружений не объединяются. Содержимое ParameterSet и массивы
репозитория шаблонов не проверяются.

## Входные параметры

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Влияние |
| --- | --- | --- | --- | --- | --- |
| `index` | Discovery → `check` | Да | Нет | `RepoIndex` | Окружения, привязки и обнаруженные файлы |
| `connections` | Вызывающий код → `check` | Нет | `None`: `compute_connections(index)` | `Connections` | Выбранные физические файлы и их использования |

## Ход обработки

1. **Выбрать подключённые ссылки**

   1. Использовать переданные `connections` или вычислить их из `index`.
   2. Собрать уникальные кортежи `(environment, category, target, reference)` из
      `connections.parameter_uses`. Имя должно разрешаться в физический файл
      для данного окружения.

2. **Сгруппировать исходные вхождения привязок**

   1. Для каждого окружения перебрать категории по порядку: `deploy`
      (`envSpecificParamsets`), `e2e` (`envSpecificE2EParamsets`), `technical`
      (`envSpecificTechnicalParamsets`). Все поля находятся под `envTemplate`.
   2. Для каждой цели перебрать исходный список ссылок с индексами. Пропустить
      вхождения, отсутствующие среди выбранных кортежей, не меняя последующие индексы.
   3. Для выбранного имени сохранить уникальные категории и все пути
      `("envTemplate", category.binding_field, target, original_list_index)`.
      Сравнивать имена точно как в `RepoIndex`, сохраняя регистр и суффиксы.
   4. Оставить имена минимум в двух категориях. Если конфликтов нет, перейти к
      следующему окружению, не перечитывая его определение.

3. **Найти позиции конфликтующих ссылок**

   1. Один раз загрузить `<env>/Inventory/env_definition.yml` для окружения.
   2. Для каждого конфликтующего имени получить позиции всех сохранённых путей
      через `LoadedYaml.position`.
   3. Удалить одинаковые пары `(line, column)` и отсортировать их. Повторы ссылки
      внутри одной категории сохраняются как позиции, если их координаты различаются.
      YAML-алиасы, дающие одинаковую позицию, не дублируют её.
   4. Сделать первую позицию основной и сохранить все позиции в замечании.

4. **Сформировать замечания**

   1. Выдать одно Warning / Fix на окружение и конфликтующее имя ссылки.
   2. Соединить названия участвующих категорий через `", "` в порядке
      `deploy`, `e2e`, `technical`.
   3. Отсортировать замечания по `(path.as_posix(), key, line)`.

## Результат

Каждое замечание содержит правило `PLACE-7`, severity `warning`, тип `Warning`,
действие `Fix`, точное имя ссылки в `key`, `<cluster>/<env>` в `scope` и пустой
`related`. Путь указывает на определение окружения. `locations` содержит все
различающиеся позиции; первая задаёт основные строку и столбец.

Сообщение: `ParameterSet {name!r} is bound to multiple categories: {categories}.`

Подсказка: `Use a separate ParameterSet for each category, even when the parameter values are identical.`

Консоль и HTML используют описание `One category per ParameterSet` и располагают
правило после PLACE-6 и перед PLACE-8. Пустой блок — `PLACE-7
No findings`;
HTML показывает все позиции и метки Warning / Fix. Сами эти предупреждения
сохраняют код завершения 0. Другие правила могут независимо сообщать о той же
ссылке. Конфигурация не изменяется.

## Обработка ошибок

**2a.** Неразрешившиеся ссылки исключаются с сохранением исходных индексов.
Несколько выбранных физических файлов не добавляют категории или замечания.

**3a.** `YamlReadError` подавляет замечания PLACE-7 данного окружения;
обработка следующего окружения продолжается.

**3b.** При отсутствии точной позиции вхождения `LoadedYaml.position` сохраняет
последнюю доступную позицию предка; начальная позиция — строка 1, столбец 1.

## Пример

Пусть `shared` разрешается, а `missing` — нет:

```yaml
envTemplate:
  envSpecificParamsets:
    cloud: [missing, shared, shared]
  envSpecificTechnicalParamsets:
    bss: [shared]
```

Результат — одно Warning / Fix с сообщением
`ParameterSet 'shared' is bound to multiple categories: deploy, technical.`
Позиции указывают на исходные индексы 1 и 2 списка deploy и индекс 0 списка
technical. Отсутствующая ссылка не сдвигает индексы.

Раздельные имена `shared-deploy` и `shared-technical` устраняют конфликт даже
при одинаковых значениях параметров.

Запускаемые синтетические примеры: [конфликт](../../../testdata/place7/not-ok/environments/lab-cluster/e01/Inventory/env_definition.yml)
и [допустимые привязки](../../../testdata/place7/ok/environments/lab-cluster/e01/Inventory/env_definition.yml).
