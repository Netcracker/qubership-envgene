## Описание

PLACE-2 находит значения подключённых ParameterSet, которые повторяют уже заданное значение вместо изменения. Сначала сравниваются значения уровня environment с входами repository/cluster, затем значения cluster с repository. Сравнения repository с шаблоном нет.

## Входные параметры

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Назначение |
| --- | --- | --- | --- | --- | --- |
| `index` | Обнаружение репозитория | Да | Нет | `RepoIndex` | Кластеры и найденные окружения |
| `full` | Effective Set | Да | Нет | Окружение → области → значения | Входы repository + cluster + environment |
| `lower` | Effective Set | Да | Нет | Та же структура | Входы repository + cluster |
| `site` | Effective Set | Да | Нет | Та же структура | Только входы repository |

## Ход обработки

1. **Получить проекции окружения**

   1. Использовать реальные выбранные входы, разрешённые до фильтрации уровней. Не возвращать затенённые файлы.
   2. Для каждого найденного окружения получить `full`, `lower`, `site`. Если хотя бы одна проекция отсутствует, пропустить окружение.
   3. Использовать единое множество уже выданных замечаний на весь запуск правила.

2. **Проверить повторы уровня environment**

   1. Перебрать области и конечные значения `full`; оставить только значения с уровнем происхождения environment.
   2. Найти ту же область и путь ключа в `lower`.
   3. Если значения нет или оно отличается, пропустить. Если равно, перейти к шагу 4.

3. **Проверить повторы уровня cluster**

   Повторить шаг 2 для `lower` относительно `site`, оставляя значения уровня cluster. Для каждого окружения это сравнение выполняется после шага 2.

4. **Убрать дубли и сформировать замечания**

   1. Маркер — `(путь исходного файла, ключ через точку)`; он общий для обоих сравнений и всех окружений. Область сравнения в маркер не входит.
   2. Повторный маркер пропустить. Для нового создать замечание на позиции повторяющего значения в YAML.
   3. Владельцем области для environment считать полное имя окружения; для cluster — кластер исходного файла, при его отсутствии `repository`.
   4. Сохранить источник нижележащего значения в `related`. Вернуть замечания в порядке обнаружения.

## Результат

Каждый повтор даёт Warning / Fix. Сообщение указывает ключ и уровень повторения. Подсказка предлагает удалить ключ из этого файла либо изменить значение, если переопределение намеренное. Основная позиция указывает на повтор, а не на исходное значение. Файлы не изменяются. Пустой результат отображается как `No findings`; замечания сохраняют код CLI `0`.

## Обработка ошибок

**1a.** Неразрешившиеся ссылки, неотрендеренный Jinja и нечитаемые ParameterSet не дают пригодных значений. Сообщения обнаружения/разрешения входов выводятся отдельно.

**1b.** Если проекция отсутствует, окружение пропускается.

**2a / 3a.** Отсутствующее нижележащее значение означает новый вклад, отличающееся — настоящее переопределение. Замечания PLACE-2 нет.

**4a.** Повторное обнаружение одного файла/ключа подавляется, включая общие кластерные файлы и несколько целей подключения.

## Пример

Окружение подключает `[shared, env-deploy]` через `envSpecificParamsets.cloud`:

```yaml
# environments/c/parameters/shared.yml
name: shared
parameters:
  LOG_LEVEL: info
  REPLICAS: 2
```

```yaml
# environments/c/e/Inventory/parameters/env-deploy.yml
name: env-deploy
parameters:
  LOG_LEVEL: info
  REPLICAS: 3
```

Одно замечание указывает на `LOG_LEVEL` окружения. `REPLICAS` действительно изменён и замечания не даёт.

Для сравнения cluster с repository подходят файлы `environments/parameters/shared.yaml` и `environments/c/parameters/shared.yml`: оба могут сохраниться при разрешении. Одинаковое полное имя файла на этих уровнях затенило бы repository-файл, поэтому такой пример не доказывает повтор между двумя участвующими входами.
