## Описание

PLACE-8 (SHOULD) проверяет часть правила о пустых сущностях: подключённые пустые
ParameterSet, Resource Profile Override и файлы credentials получают Information / Review.
Физический файл должна выбирать видимая привязка или известное использование
генератором. Проверка человеком определяет, намеренно ли оставлен пустой слот;
файлы не изменяются и не удаляются. Размер, число приложений, имена сервисов и
префиксы параметров не используются как признаки смешения обязанностей.

## Входные параметры

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Влияние |
| --- | --- | --- | --- | --- | --- |
| `index` | Discovery → `check` | Да | Нет | `RepoIndex` | Окружения, привязки и обнаруженные файлы |
| `connections` | Вызывающий код → `check` | Нет | `None`: `compute_connections(index)` | `Connections` | Выбранные физические файлы и их использования |

## Ход обработки

1. **Разрешить подключения физических файлов**

   1. Использовать переданные `connections` или вычислить их из `index`. Discovery
      предоставляет записи из `environments/` репозитория, кластеров и `Inventory/`
      окружений. Профили и credentials ищутся рекурсивно. Сгенерированные
      `<env>/Profiles` и `<env>/Credentials` вне Inventory, `.git`, пути за пределами
      репозитория и шаблоны Jinja исключены. Глубина поиска ParameterSet сохраняется.
   2. Разрешить списки ParameterSet в `envSpecificParamsets`, `envSpecificE2EParamsets`
      и `envSpecificTechnicalParamsets` общим алгоритмом подготовки. Файл кластера
      заменяет файл репозитория с тем же подготовленным именем; файлы окружения
      также участвуют. Сохранить все оставшиеся физические пути.
   3. Разрешить `envSpecificResourceProfiles` (цель → ссылка) и
      `sharedMasterCredentialFiles` (список ссылок) под `envTemplate`.
      Искать сначала в Inventory, затем в его кластере, затем в `environments/`
      репозитория. На каждом уровне для профилей использовать `resource_profiles`,
      `rp_override`, `Profiles`, `parameters`; для credentials — `credentials`,
      `Credentials`, `shared-credentials`.
   4. Точно сопоставлять имена `.yml`/`.yaml` без расширения, включая индексированные
      пути-алиасы, не нормализуя ссылки. Выбрать все совпадения первого занятого
      каталога и остановиться. Ошибочный YAML также занимает позицию и затеняет
      каталоги меньшего приоритета.
   5. Включить точный путь `Inventory/credentials/inventory_generation_creds.yml`
      каждого обнаруженного окружения, если файл есть в индексе. Этот известный
      вход генератора подключён и без явной привязки. Одноимённые файлы кластера
      и репозитория не получают неявного использования. Привязки шаблонов и
      другие способы использования не предполагаются.

2. **Собрать и классифицировать кандидатов**

   1. Начать с подключённых ParameterSet, добавить подключённые профили, затем
      credentials. Удалить повторы по разрешённому физическому пути между
      окружениями и типами; записи credentials имеют приоритет. Путь должен
      присутствовать в `connections.selected_paths`.
   2. Профили из устаревшего `parameters/` первоначально считать кандидатами
      ParameterSet. Переклассифицировать такого кандидата в профиль, если его
      выбирает привязка профиля или какое-либо отображение в списке `applications`
      содержит поле `services`.
   3. При переклассификации пропустить смешанную структуру, если хотя бы одно
      отображение приложения содержит `parameters`, даже пустое или null.
   4. Пропустить записи Jinja и записи без загруженного YAML. Каждый оставшийся
      файл проверить один раз по итоговому типу.

3. **Проверить структурную пустоту**

   1. Загруженный корневой null, включая пустой документ или только комментарии,
      считается пустым. Другой корень, не являющийся отображением, включая `[]`, неизвестен.
   2. Для ParameterSet разрешить только корневые ключи `name`, `version`,
      `description`, `parameters`, `applications`. Сначала проверить корневой
      `parameters`, затем `applications[].parameters`: любое непустое отображение
      означает непустой файл. Ключ учитывается при любом значении, включая null,
      `false`, `0`, `""`, `{}` и `[]`.
   3. Для профиля разрешить только `name`, `version`, `description`, `baseline`,
      `applications`. Обойти приложения и сервисы в исходном порядке. Любой непустой
      список `applications[].services[].parameters` означает непустой файл, даже
      если его элементы неполные. Сам `baseline` содержимого не добавляет:
      подключённый профиль только с baseline остаётся пустым и получает Information / Review.
   4. Отсутствующие контейнеры не добавляют содержимого. Присутствующие контейнеры
      параметров должны иметь указанный выше тип отображения/списка; applications
      и services должны быть списками отображений. Явный null или неверный тип
      дают неизвестное состояние. Обход завершается на первом решающем неизвестном
      или непустом состоянии; это не проверка схемы. Если обход завершён без них,
      файл пуст. Одни имена содержимого не добавляют.
   5. Для credentials пустое отображение пусто, а любая корневая запись означает
      непустой файл. Значения секретов не проверяются и не расшифровываются.

4. **Сформировать замечания**

   1. Выдать замечание только при определённо пустом результате. Неизвестные и
      непустые структуры пропустить.
   2. Установить строку 1, столбец 1 и отсортировать по `(path.as_posix(), key, line)`.

## Результат

Возвращается список `PLACE-8` с severity `information`, типом `Information` и
действием `Review`. `key` — имя файла без расширения; позиция одна, `related` пуст.
`scope` — `repository`, `<cluster>` или `<cluster>/<env>`.

Сообщение: `{kind} {filename!r} is empty but is referenced or used by the generator.`

`kind` — `ParameterSet`, `Resource Profile Override` или `Credentials file`.

Подсказка: `Review whether this empty file is intentional. If not, populate it or remove its reference or usage.`

Описание в каталоге: `Referenced or used entities are empty`. Консоль и HTML
располагают PLACE-8 после PLACE-7 и перед PLACE-9; пустой блок — `PLACE-8
No findings`.
HTML показывает Information / Review. Сами эти замечания сохраняют код завершения 0.
Новых опций и автоматических исправлений нет. Классификация устаревших файлов не
меняет другие правила и не добавляет сущности в NAME-2.

## Обработка ошибок

**1a.** Отсутствующие или неверные контейнеры привязок не дают применимой ссылки.
Неразрешившиеся ссылки и ссылки только из шаблонов не добавляют кандидатов.
Отсутствие inventory-generation credentials допустимо и не даёт замечания.

**1b.** Совпавший ошибочный YAML затеняет каталоги меньшего приоритета, но
пропускается на шаге 2. Сообщения discovery об ошибках чтения добавленных типов
содержат путь и общую причину без фрагментов YAML и значений credentials.

**2a.** Незагруженные файлы, Jinja и смешанная структура устаревшего профиля не дают замечаний.

**3a.** Неизвестная структура не даёт замечания. Неподдерживаемые корневые метаданные,
включая неизвестные метаданные шифрования, не позволяют признать ParameterSet или
профиль пустым. Метаданные credentials сами являются корневой записью и делают файл непустым.

## Пример

Эти синтетические привязки выбирают три файла, целиком содержащие `{}`:

```yaml
envTemplate:
  name: composite
  envSpecificParamsets:
    bss: [empty]
  envSpecificResourceProfiles:
    bss: empty-profile
  sharedMasterCredentialFiles: [empty-creds]
```

Результат — три Information / Review, по одному на файл. Замена содержимого профиля
на `baseline: standard` сохраняет его Information / Review. Удаление привязок
делает файлы неподключёнными и убирает замечания, если их независимо не выбирает
известное использование генератором.

```bash
.venv/bin/envgene-linter check testdata/place8/not-ok
.venv/bin/envgene-linter check testdata/place8/ok
```

Пример [not-ok](../../../testdata/place8/not-ok/environments/lab-cluster/e01/Inventory/env_definition.yml)
даёт три замечания PLACE-8; пример [ok](../../../testdata/place8/ok/environments/lab-cluster/e01/Inventory/env_definition.yml)
оставляет три пустых файла неподключёнными и не даёт замечаний.
