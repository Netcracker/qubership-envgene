## Описание

PLACE-10 (MUST) напрямую сравнивает каталог подключённой сущности с каталогом, установленным для её типа. Правильный каталог не даёт замечания; неправильный даёт Warning / Fix. Проверка самостоятельная, в том числе при пересечении с PLACE-9.

| Тип | Требуемый каталог |
| --- | --- |
| ParameterSet | `parameters/` |
| Resource Profile Override | `resource_profiles/` |
| Shared Template Variables | `shared-template-variables/` |
| Shared credentials | `credentials/` |
| Cloud Passport | `cloud-passport/` |

Тип определяется подтверждённым подключением, не догадкой по содержимому YAML. Неиспользуемые файлы и неразрешившиеся ссылки в проверку не входят.

## Входные параметры

| Параметр | Источник | Обязательный | По умолчанию | Значения / формат | Назначение |
| --- | --- | --- | --- | --- | --- |
| `index` | Обнаружение репозитория | Да | Нет | `RepoIndex` | Корень репозитория и пути известных уровней |
| `connections` | Движок / общий отбор | Нет | Вычисляется, если не передан | Выбранные физические пути по типам | Проверяемые файлы и типы сущностей |
| `envTemplate.sharedTemplateVariables` | Определение окружения | Нет | Пустой список | Точные имена файлов без расширения | Подтверждает использование Shared Template Variables в дополнение к существующему отбору |

## Ход обработки

1. **Выбрать подключённые файлы известных типов**

   1. Использовать переданный индекс подключений либо вычислить его по обнаруженному репозиторию.
   2. Собрать выбранные ParameterSet, Resource Profile Override, Shared Template Variables, shared credentials и Cloud Passport.
   3. Каждый физический файл учитывать один раз на тип. Файл, используемый как два типа, должен удовлетворять требованию каждого типа независимо.

2. **Разрешить привязки Shared Template Variables**

   1. Прочитать строковые элементы списка `envTemplate.sharedTemplateVariables`. Неверные контейнеры, нестроковые элементы и динамические ссылки Jinja пропустить.
   2. Искать по порядку: Inventory/configuration, Inventory/configurations, cluster/configuration, cluster/configurations, environments/configuration, environments/configurations, затем непосредственно Inventory.
   3. В каждом каталоге рекурсивно искать точный stem `.yml`/`.yaml`, сохраняя порядок первого совпадения локального генератора. Остановиться на первом файле; одноимённые файлы не сливать.
   4. Не переходить по символьным ссылкам каталогов и не обходить `.git`. Небезопасный или внешний совпавший файл пропустить без выбора следующего файла меньшего приоритета. Для установления использования содержимое YAML не нужно.
   5. Добавить выбранные пути в общие подключения и подключения окружения. Канонический Inventory/shared-template-variables находится через заключительный поиск в Inventory. Использование неразрешившихся каталогов не предполагать.

3. **Определить фактический уровень и каталог**

   1. Разрешить физический путь; исключить внешние пути и `.git`.
   2. Выбрать наиболее глубокую известную базу: Inventory окружения, каталог кластера либо корневой environments.
   3. Сравнить первый компонент каталога ниже базы с точным каталогом типа. Вложенность внутри правильного каталога допустима; его имя внутри другого каталога не делает размещение правильным.
   4. Если выбранный физический файл находится внутри репозитория, но вне этих баз, считать его размещённым неправильно; базой рекомендации выбрать корневой environments.

4. **Сформировать замечания о несовпадении**

   1. Каталог совпадает — замечания нет. Не совпадает — создать Warning / Fix с типом, файлом и ожидаемым каталогом.
   2. Указать соответствующий выбранный файл на позиции `1:1`; содержимое не читать, файлы не переименовывать и не перемещать.
   3. Не подавлять замечание из-за срабатывания другого правила на том же файле. Убирать только повторы пары физический файл/тип.
   4. Отсортировать замечания по пути, ключу и строке.

## Результат

Результат — замечания `PLACE-10`, severity `warning`, тип `Warning`, действие `Fix`, stem файла как ключ и фактический уровень как scope. Позиция одна, `1:1`; подсказка называет ожидаемый каталог.

Описание каталога: `Entities belong in their type directories`. Консоль всегда печатает тринадцать заголовков; PLACE-10 расположен после PLACE-9 и перед NAME-1. Пустой блок показывает `No findings`. HTML сохраняет только разделы с замечаниями. Код завершения CLI остаётся `0`; новых флагов и автоматических изменений нет.

## Обработка ошибок

**1a.** Неиспользуемые файлы, неразрешившиеся ссылки и невыбранные неоднозначные паспорта замечаний не дают. Существующие ограничения выбора Jinja сохраняются.

**2a.** Локальный генератор разрешает Shared Template Variables через старые каталоги configuration, а PLACE-10 требует `shared-template-variables/`. Правило сообщает о неправильном каталоге используемого файла, не меняет поиск генератора и не предполагает поддержку новых путей.

**2b / 3a.** Внешние пути и `.git` исключаются. Небезопасное совпадение не должно делать файл меньшего приоритета используемым.

**4a.** Ошибочный или пустой YAML не отменяет проверку размещения, если использование подтверждено. Правило не угадывает тип по данным, не проверяет схемы, не читает credentials и не проверяет отсутствующие файлы.

## Пример

Выбранный ParameterSet в `Inventory/parameters/service-deploy.yml` проходит проверку. Выбранный Resource Profile Override в `Inventory/parameters/service-profile.yml` — нет: ему нужен каталог `resource_profiles/`.

```yaml
# Inventory/env_definition.yml
envTemplate:
  envSpecificResourceProfiles:
    cloud: service-profile
```

Если выбран `Inventory/rp_override/service-profile.yml`, PLACE-10 выдаёт предупреждение на этот файл и предлагает `Inventory/resource_profiles/`. Неподключённая копия в `rp_override/` пропускается.

Shared credentials из `shared-credentials/` нарушают правило каталога, хотя генератор умеет их находить. Выбранный паспорт в `cloud-passports/` даёт PLACE-10 независимо от PLACE-9.

Shared Template Variables, подключённые как `common` из `Inventory/configuration/common.yml`, должны находиться в `Inventory/shared-template-variables/`. Выбранный вложенный `Inventory/resource_profiles/team/service-profile.yml` допустим; `Inventory/parameters/resource_profiles/service-profile.yml` — нет.
