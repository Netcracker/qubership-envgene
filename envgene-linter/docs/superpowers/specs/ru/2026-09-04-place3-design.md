# envgene-linter: PLACE-3

Отбор проверяемых файлов определяется более поздним общим [правилом подключённости](../2026-09-11-connected-only-design.md).

Это первоначальный проект из трёх проверок. Позднее [PLACE-4](2026-09-07-place4-design.md) заменил проверки ключей в ParameterSet; актуальный PLACE-3 проверяет только расположение файлов passport. Общее правило подключённости также исключает невыбранные passport из замечаний о расположении и из каталогов ключей. Разделы ниже о каталогах и трёх проверках сохраняют историю; актуальное поведение — в [алгоритме](../../../algorithms/ru/place3.md).

Дата: 2026-09-04  
Статус на момент проектирования: принят в разговоре, ждёт проверки файла\
Английская версия: [../2026-09-04-place3-design.md](../2026-09-04-place3-design.md)

## Зачем

Термины: `env` — окружение; привязка — ссылка из `env_definition.yml` на набор параметров; `scope` — область «цель × категория», при необходимости отдельно для приложения. Effective Set — итоговые значения после объединения ParameterSet; `discovery` — обнаружение файлов и чтение привязок.

`envgene-linter check <repo>` печатает PLACE-1, потом PLACE-2, потом PLACE-3.

PLACE-3 (SHOULD): ключ контракта Cloud Passport живёт на **кластере**. На env — только если значение реально другое. Файл passport — в `cloud-passport/` (или `cloud-passports/`) этого кластера. Это warning. Коды выхода те же.

## Простыми словами

Passport описывает платформу и физический кластер. Его содержимое общее для всех env на кластере. Копировать его в каждый env или в `environments/parameters/` — неправильный слой.

PLACE-1: «одно и то же во всех env — подними выше» (любой ключ).  
PLACE-2: «окружение или кластер повторили унаследованное значение — удали копию».\
PLACE-3: «это ключ контракта или файл passport — ему место на кластере, если env не поменял значение».

Привязки по-прежнему из `env_definition` (`envSpecific*` и `inventory.cloudPassport`). ParameterSet без привязки Effective Set не видит.

Значения passport в этом цикле **не** объединяются с Effective Set.

## Что не делаем в этом цикле

- Объединять passport с проекциями Effective Set
- PLACE-4 («пиши ключ в `passport.yml`, не в ParameterSet»)
- Template, Jinja-passport / Jinja-ParameterSet (пропуск + заметка в stderr)
- `--rules`, JSON/HTML, baseline, `[EXCEPTION …]`, autofix

## Что меняем в коде

Discovery должен увидеть файлы passport и поле `inventory.cloudPassport`. Объединение Effective Set не меняется.

## Каталог ключей (первоначальный проект)

Два источника, объединяем.

### Таблица EnvGene (всегда)

Закрытый список имён в Effective Set **и** ключей YAML passport, которые им соответствуют. Источник: `docs/features/cloud-passport-processing.md` на `feature/modern-toolset`. Если имена разные — оба (`MAAS_SERVICE_ADDRESS` и `MAAS_EXTERNAL_ROUTE`; `DBAAS_CLUSTER_DBA_CREDENTIALS_USERNAME` и `DBAAS_AGGREGATOR_USERNAME`; `VAULT_AUTH_ROLE_ID` и `VAULT_TOKEN`; `CLOUD_DEPLOY_TOKEN`, даже если в Effective Set его нет).

Производные записи из той же таблицы: `DBAAS_ENABLED`, `MAAS_ENABLED`, `VAULT_ENABLED`, `PUBLIC_VAULT_URL`.

Список — константа в коде. Markdown во время проверки не читается.

### Ключи из выбранного passport

Все отображения ключей в секциях, кроме `version`. Разворачиваем один уровень: имя секции в ключ ParameterSet не входит. `dbaas.DBAAS_AGGREGATOR_ADDRESS` даёт `DBAAS_AGGREGATOR_ADDRESS`. Вложенные карты внутри секции не берём (у генератора секции плоские).

Нечитаемый или Jinja-passport: файл пропускаем, заметка в stderr, ключи не добавляем.

### Какой каталог где

- **Каталог env** = таблица ∪ ключи passport, выбранного для этого окружения. Если passport не выбран — только таблица.
- **Каталог кластера** = таблица ∪ объединение каталогов env кластера ∪ ключи из файлов passport в `cloud-passport/` или `cloud-passports/` этого кластера (в первоначальном проекте файл добавлял ключи в каталог, даже если ни одно окружение его не выбрало).
- **Каталог репозитория** = таблица ∪ объединение каталогов всех кластеров.

PLACE-3 и исключение PLACE-1 сопоставляют **верхний ключ** листа — первый компонент пути (`DBAAS_AGGREGATOR_ADDRESS`, без вложенных компонентов).

## Как выбирается passport

Первоначальный список ниже не уточнял, считаются ли явные совпадения сразу на всех уровнях или отдельно на каждом. Для текущего поведения используйте [спецификацию PLACE-9](2026-09-11-place9-design.md): явный поиск собирает кандидатов по перечисленным базам, автоматический останавливается на первой непустой группе имени. Это примечание указывает актуальный источник, не придумывая исторический приоритет.

Как генератор (`find_cloud_passport_definition` / `find_passport_by_env_definition`). При ошибке выбора линтер **не** прекращает проверку, даже если генератор завершился бы с ошибкой.

Для каждого env, по порядку:

1. Если `inventory.cloudPassport` — непустая строка, ищем `<имя>.yml` или `<имя>.yaml` (не creds) в `cloud-passport/` и `cloud-passports/`, рекурсивно, на уровнях:
   - `<env>/Inventory/`
   - каталог кластера
   - `environments/` instance-репо
   - Ноль или больше одного файла — passport не выбирается. Заметка в stderr. Каталог env = таблица.
2. Если поля нет или оно пустое — auto **только** в каталоге кластера, в таком порядке:
   - `cloud-passport/<имя-кластера>.yml|.yaml`
   - `cloud-passport/passport.yml|.yaml`
   - Auto смотрит только `cloud-passport` (не `cloud-passports`), как генератор.
   - Нет файла — passport нет, каталог = таблица.
   - Больше одного на одном шаге — passport не выбирается. Заметка в stderr.

`*-creds.yml` и файлы в `credentials/` / `Credentials/` — не passport.

## Файл «на кластере»

Passport на кластере, если путь начинается с:

`environments/<cluster>/cloud-passport/` или `environments/<cluster>/cloud-passports/`

и `<cluster>` — кластер, найденный при обходе репозитория.

Любой другой найденный passport YAML — замечание: `environments/cloud-passport/`, `Inventory/cloud-passport/` у env, и т.п. Одно замечание на файл. Подсказка: перенести в `environments/<cluster>/cloud-passport/`. Если путь определяет кластер-владелец, указываем его в подсказке; иначе рекомендуем `cloud-passport/` одного из кластеров без выбора конкретного.

Ищем кандидатов: `cloud-passport/` и `cloud-passports/` под `environments/`, под каждым кластером и под `Inventory/` каждого env. Эти папки по-прежнему не кластеры и не env.

## Три проверки (первоначальный проект)

### 1. Файл не на кластере

Каждый проиндексированный passport YAML не на кластере → один warning PLACE-3 (строка 1, если лучше нет).

### 2. Ключ контракта на слое репозитория

В проекции **site** лист написан на `repository`, верхний ключ есть в **каталоге репозитория** → warning. Повторные замечания с одинаковой парой `(файл, верхний ключ)` исключаются, в том числе между областями.

Подсказка: перенеси ключ на кластер.

### 3. Один и тот же ключ в нескольких env

Для каждого кластера отдельно:

1. У каждого env берём листья, написанные на `environment` в `full`, верхний ключ есть в **каталоге этого env**.
2. Исключаем повтор относительно `lower` (тот же ключ и значение уже в ParameterSet’ах репозитория+кластера). Это только PLACE-2.
3. Участники для `(scope, path)` — env, у которых этот лист остался.
4. Замечание, если участников **не меньше двух** и они пишут один путь с одним значением.

Один env — замечания нет (переопределение или единственный источник). Разные значения — замечания нет.

Основная позиция — первое окружение по алфавитному порядку имён, как в PLACE-1. Подсказка: перенести ключ на кластер; в окружении оставить только отличающееся значение. Остальные участники перечисляются в `related`; консоль может не выводить это поле, как в PLACE-2.

Повторные замечания с одинаковой парой `(файл, верхний ключ)` исключаются между областями.

## Исключение ключей каталога из PLACE-1

- Env → кластер: не поднимаем лист, если верхний ключ в каталоге этого env.
- Кластер → репозиторий: не поднимаем лист, если верхний ключ в каталоге этого кластера.

PLACE-2 не трогаем.

## Отчёт

Тот же блок из четырёх строк. Всегда три заголовка, с замечаниями или `No findings`.

```
PLACE-1
…

PLACE-2
…

PLACE-3
<path>:<line>
warning
<message>
<hint>
```

Смысл сообщений:

- Файл: passport `<stem>` лежит не на слое кластера.
- Ключ репозитория: ключ `<key>` из контракта Cloud Passport написан на слое репозитория.
- Env: ключ `<key>` из контракта повторяется в env кластера `<cluster>`.

Выход: `0` на warning, `2` если нет `environments/` или некорректны аргументы команды.

## Тесты

Пишем вместе с правилом:

- Явный `cloudPassport` выбирается; auto `passport.yml` выбирается; нет passport — только таблица.
- Два явных совпадения — passport не выбран, заметка stderr, только таблица.
- Файл в `environments/cloud-passport/` — замечание на файл.
- Файл в `Inventory/cloud-passport/` у env — замечание на файл.
- Файл в `environments/<cluster>/cloud-passport/` — файла в отчёте нет.
- Ключ таблицы в `environments/parameters/` — замечание на репозиторий.
- Свободный ключ только из passport кластера, тот же ключ на репозитории — замечание.
- Два env, один ключ каталога, одно значение, в `lower` нет — один PLACE-3; PLACE-1 этот ключ не пишет.
- Один env — замечаний нет.
- Два env, разные значения — замечаний нет.
- Env повторил кластерный ParameterSet — только PLACE-2.
- Примеры: `testdata/place3/ok` и `testdata/place3/not-ok`.
