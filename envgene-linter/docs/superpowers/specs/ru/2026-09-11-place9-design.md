# PLACE-9: количество и размещение используемых Cloud Passport

Статус: реализовано. Пользователь согласовал определение роли infra по точному имени `passport-infra`.
Английская версия: [2026-09-11-place9-design.md](../2026-09-11-place9-design.md).

## Назначение и область проверки

Каждый использующий кластер может иметь не более одного выбранного паспорта default и одного infra. Использующий кластер — кластер окружения, которое подключает паспорт. Имя без расширения `.yml` или `.yaml` называется stem: ровно `passport-infra` означает infra, любое другое выбранное имя — default. Это классификация роли, а не проверка имени по NAME-8/9.

Проверять только паспорта, найденные через `inventory.cloudPassport` или существующий автоматический поиск. Неразрешившиеся ссылки, отсутствующие паспорта или credentials и неиспользуемые файлы не дают замечаний. Содержимое credentials не проверяется.

Физический файл — цель после разрешения символьных ссылок. Несколько путей к одной цели считаются одним файлом. Внешние пути и пути внутри `.git` исключаются.

## Неоднозначный поиск паспорта

Попытка поиска может установить конфликт, даже если выбрать один паспорт невозможно. Это явное исключение PLACE-9 из обычной области выбранных файлов: кандидаты использованной попытки участвуют в проверке неоднозначности, но не в проверках содержимого.

1. Для явной ссылки собрать совпавшие файлы в существующих каталогах поиска паспортов на уровнях Inventory, кластера и репозитория.
2. При автоматическом поиске сначала искать паспорт с именем кластера, затем `passport`. Остановиться на первой непустой группе кандидатов; резервные имена не объединять.
3. Убрать повторы физических путей. Если использованная попытка имеет несколько разных кандидатов, выдать одно замечание о неоднозначности для этого набора.
4. Если окружения встречают один и тот же набор кандидатов, объединить их в одно замечание. Включить все файлы-кандидаты на позиции `1:1` и позиции всех затронутых привязок в определениях окружений. Для автоматического поиска указать `1:1` определения.

Использовать структурированные данные кандидатов, а не разбор текста сообщений о пропуске. Сохранить поведение успешного выбора для остальных правил.

## Количество выбранных паспортов

Сгруппировать успешно выбранные физические файлы по использующему кластеру и роли. Использование одного файла несколькими окружениями не увеличивает количество.

Если для роли выбрано больше одного физического файла, выдать одно Warning / Fix с этими паспортами. Не считать повторно неоднозначные группы кандидатов.

Примеры:

- Один `passport.yml` и один явно выбранный `passport-infra.yml` — допустимо.
- Используемые `business-a.yml` и `business-b.yml` — два паспорта default, одно замечание о количестве.
- Неподключённый `backup.yml` — не влияет на количество.

## Каталог паспорта

PLACE-3 проверяет размещение выбранного паспорта вне уровня кластера. PLACE-9 не повторяет это замечание об уровне.

Для выбранного паспорта на уровне кластера требуется канонический каталог `cloud-passport/` этого кластера. Вариант `cloud-passports/` во множественном числе неправильный. Вложенные каталоги внутри `cloud-passport/` допустимы.

## Используемые credentials паспорта

Для каждого однозначно выбранного паспорта использовать точный порядок поиска локального генератора относительно родительского каталога паспорта:

1. `credentials/<имя-паспорта-без-расширения>.yml`
2. `<имя-паспорта-без-расширения>-creds.yml`

Используется только первый существующий файл. Если его цель находится вне репозитория или внутри `.git`, пропустить проверку сопутствующего файла без выбора второго пути. Не предполагать поиск credentials с расширением `.yaml`: локальный загрузчик проверяет только перечисленные `.yml` пути. Сами паспорта поддерживают оба расширения.

Используемый файл credentials должен лежать рядом с паспортом в правильном каталоге кластера `cloud-passport/`. Поэтому выбранный файл из подкаталога `credentials/<stem>.yml` вызывает замечание, даже если рядом есть неиспользуемая копия `<stem>-creds.yml`.

Выдать одно замечание на неправильно размещённый используемый физический файл credentials, указав его позицию и связанный паспорт. Отсутствующие файлы и неиспользуемые копии меньшего приоритета пропускаются. Содержимое credentials для этого правила не читается.

## Замечания и отчёт

Сортировать по пути, ключу и строке. Все замечания — Warning / Fix; код завершения CLI остаётся `0`. Описание каталога: `One Cloud Passport per cluster`. Нет автоматических изменений, новых флагов CLI, сетевых обращений или вывода значений исходных данных.

При введении PLACE-9 добавлял двенадцатый заголовок консоли после PLACE-8 и перед NAME-1. Позже [PLACE-10](2026-09-11-place10-design.md) добавил заголовок между PLACE-9 и NAME-1; сейчас их тринадцать. Консоль всегда показывает все заголовки каталога правил. HTML содержит только разделы с замечаниями в том же порядке правил.

## Проверка реализации и документация

Использовать синтетические примеры:

- Автоматический default; default вместе с явно выбранным infra; несколько используемых нестандартных имён default; лишние неподключённые файлы и неразрешившиеся ссылки.
- Явные дубликаты на разных уровнях, неоднозначность `.yml`/`.yaml`, повтор одного конфликта в разных окружениях и приоритет автоматического поиска.
- Несколько путей к одному файлу, внешние и `.git` пути, некорректные выбранные паспорта, которые всё равно учитываются.
- Замечание об уровне только от PLACE-3, каталог паспортов во множественном числе и допустимая вложенность.
- Правильные credentials рядом с паспортом, используемые credentials в подкаталоге при наличии соседней копии, отсутствующие и неиспользуемые credentials.
- Одинаковый результат прямого вызова и движка, точные позиции привязок, консоль и HTML.

Описать алгоритм на русском и английском в согласованном формате из семи разделов. Исторические решения сохранять с явными примечаниями о замене, если последующие правила меняют общую область проверки или отчёт.
