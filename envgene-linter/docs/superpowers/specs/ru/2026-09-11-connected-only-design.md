# Проверять только подключённые или используемые сущности

Статус: реализовано по просьбе пользователя ограничить все правила подключёнными сущностями, включая NAME-3.
Английская версия: [2026-09-11-connected-only-design.md](../2026-09-11-connected-only-design.md).

Эта спецификация заменяет область применимости проверок в более ранних спеках. Требования к именам, сравнению значений и отчётам сохраняются, если ниже явно не сказано обратное. Позднее [PLACE-9](2026-09-11-place9-design.md) добавляет проверку неоднозначности паспортов, а [PLACE-10](2026-09-11-place10-design.md) — отбор Shared Template Variables.

## Термины

- **Подключённый / выбранный файл:** существующий файл, выбранный для окружения по поддерживаемой локальной ссылке или известному использованию генератором.
- **Физический путь:** путь после разрешения символьных ссылок. Несколько путей подключения могут указывать на один физический файл.
- **Stem:** имя файла без расширения данных (`.yml`, `.yaml` или `.json`) и необязательного суффикса `.j2`. Совпадение имён не доказывает идентичность или подключение файлов.
- **Группа поиска (bucket):** кандидаты одного приоритета поиска. Группа занята, если найден хотя бы один подходящий файл, даже с некорректным содержимым.
- **Перекрытый файл:** вход меньшего приоритета, заменённый при разрешении ссылок; это окружение его не использует.
- **Проекция:** часть фактически выбранных входов, ограниченная определёнными уровнями репозитория, кластера или окружения.

## Общее требование

Все правила проверяют только сущности, выбранные по видимой локальной ссылке или документированному использованию генератором. Пользователь явно распространил ограничение на NAME-3. Не добавлять замечания о неразрешившихся ссылках, новые эвристики, автоматическое исправление и сетевые обращения. Неизвестное внешнее использование, шаблоны и Jinja не доказывают подключение.

Подключение определяет физический путь в контексте окружения, а не просто совпадение имени файла где-либо в репозитории. Неиспользуемый файл не может добавлять замечания, позиции, категории или ключи паспорта в результаты проверок. Сообщения о пропуске при обнаружении и загрузке остаются диагностикой обнаружения, а не замечаниями правил.

## Разрешение ссылок и общий отбор

Ввести общий модуль подключений. Движок может вычислять набор один раз и передавать его правилам. Прямой вызов правила обязан применять тот же фильтр. Сохранить совместимость существующих конструкторов моделей и их значений по умолчанию.

### ParameterSet и проекции

Использовать существующий `effective.resolve_reference(index, env, reference)` со всеми уровнями. Сохранить каждый файл, оставшийся после сборки входов, включая файлы окружения. Файл кластера с тем же именем при подготовке входов исключает файл репозитория для этого окружения. Собирать факты использования файла: окружение, категория, целевой объект и ссылка, а также выбранные пути по окружениям.

Некорректный YAML может занимать выбранное место, но проверки содержимого пропускают нечитаемые документы или неизвестные структуры. Jinja не рендерится.

Для проекций PLACE-1/2 сначала разрешить реальные входы всех уровней, затем оставить нужные уровни. Проекция не должна возвращать перекрытый файл, который окружение не использует. При необходимости сохранить прежнюю семантику низкоуровневого API `resolve_reference`; проекции `compute` должны основываться на реально подключённых входах.

### Cloud Passport

Использовать `resolve_passport`: явная ссылка `inventory.cloudPassport` и существующий документированный автоматический поиск доказывают подключение. Неразрешившиеся и неоднозначные паспорта не выбираются. Каталог контрактных ключей содержит статическую таблицу и ключи выбранных паспортов, но не посторонних файлов паспортов.

### Профили и credentials

Сохранить поиск и обработку неоднозначности PLACE-8: базы Inventory, кластера и репозитория; упорядоченные варианты имён каталогов; точные имена файлов без расширения. Все кандидаты первой занятой группы остаются выбранными, даже если некорректны; перехода к менее приоритетной группе нет.

Сохранять пути подключения для сопоставления имён, физические пути — для идентичности. Сохранить известное использование `Inventory/credentials/inventory_generation_creds.yml` в обнаруженных окружениях. Перенести или переиспользовать поиск в общем модуле без изменения результатов PLACE-8.

### Artifact Definition

Выбирать определения только через строковые `envTemplate.artifact`, `envTemplate.bgNsArtifacts.origin` и `.peer` в формате `application:version`. Нужна буквальная строка с непустыми первыми двумя частями, разделёнными двоеточием; последующие части генератор игнорирует. Значения с подстановками Jinja пропускать. Не предполагать переопределение `ENV_TEMPLATE_VERSION`, доступное только при выполнении.

Сопоставлять компонент `application` с точным именем файла без расширения в `configuration/artifact_definitions/`. `.yml` имеет приоритет над `.yaml`, даже если некорректен. Поле `name` не используется для выбора: отдельно его проверяет NAME-2.

Не выводить связи из произвольных строк, старого `templateArtifact` GAV, внешних шаблонов или недоступных входов Solution Descriptor (SD) пайплайна. Application Definition и Registry Definition пропускаются, пока локальное использование не доказано; присутствия каталога недостаточно.

Читать селекторы артефактов при обнаружении и хранить в полях `EnvModel`, пустых по умолчанию. Не читать вне репозитория и не выводить значения YAML в новых сообщениях о пропуске.

## Поведение правил

- PLACE-1/2: прежние проверки значений только по фактически выбранным входам проекций `full`, `lower` и `site`.
- PLACE-3: только неправильно размещённые выбранные паспорта.
- PLACE-4: контрактные ключи только в физически выбранных ParameterSet. Убрать глобальный отбор по совпадению имени без расширения. Нерендеренный Jinja не участвует в проверках содержимого.
- PLACE-6: проверять цель E2E только при наличии хотя бы одной ссылки, выбравшей файл. Пустые списки и списки только неразрешившихся ссылок не дают замечаний. Для подключённых файлов сохраняются прежние позиция цели и сообщение.
- PLACE-7: учитывать только ссылки, выбравшие файлы в данном окружении. Сохранять одно замечание на конфликтующую ссылку в окружении и все исходные позиции её вхождений. Фильтрация не перенумеровывает элементы исходных списков.
- PLACE-8: прежнее Information / Review для известных пустых выбранных или используемых сущностей.
- NAME-1: группировать совпадения только из выбранных физических ParameterSet, убирая повторы путей к одному файлу. Сохранить эвристику одинаковых значений и текст сообщений.
- NAME-2: выбранные физические ParameterSet и Artifact Definition. Сохранить сравнение имён и уровень замечания; невыбранные сущности пропускать.
- NAME-4: группировать категории по выбранному физическому файлу, а не глобальному имени без расширения. Не более одного замечания на файл. Использовать только категории и имена окружений/кластеров из реального использования этого файла. Разные одноимённые физические файлы не влияют на категории друг друга.
- NAME-3: выбранные файлы внутри прежней области `environments/`, используемые определения окружений и их каталоги кластеров/окружений. Каталоги namespace — только для целей разрешённых ParameterSet или Resource Profile. См. [алгоритм NAME-3](../../../algorithms/ru/name3.md).

## Последующие дополнения

[PLACE-9](2026-09-11-place9-design.md) проверяет неоднозначных кандидатов паспорта, найденных при использованной попытке поиска. Для других правил проверки содержимого это не успешно выбранные файлы. Правило также проверяет используемый сопутствующий файл credentials паспорта без чтения содержимого.

[PLACE-10](2026-09-11-place10-design.md) добавляет явные привязки `envTemplate.sharedTemplateVariables` в общие наборы выбранных файлов. Эти файлы участвуют в применимых правилах, включая NAME-3. Спецификация задаёт точный поиск генератора и объясняет отличие старых путей поиска от каталога, требуемого стандартом.

## Пример

Если окружение выбирает файл кластера, заменяющий файл репозитория с тем же именем при подготовке входов, для этого окружения участвует только файл кластера. Проекция уровня репозитория в PLACE-1 или PLACE-2 не возвращает заменённый файл. Другое окружение может использовать файл репозитория, если его собственное разрешение ссылок выбирает этот файл.

## Проверка реализации и документация

Использовать синтетические данные. Положительные тесты должны явно подключать проверяемые файлы: нельзя ослаблять их до ожидания пустых результатов. Добавить проверки неподключённых кандидатов с неправильными именами, значениями, контрактными ключами и некорректным содержимым; посторонних кластеров и одноимённых файлов; перекрытия входов; неразрешившихся ссылок; исходных позиций после фильтрации; изоляции категорий физических файлов и повторов путей к одной цели.

Проверить выбранные и невыбранные паспорта и состав каталога ключей; типы, приоритет и неподдерживаемые варианты селекторов артефактов; сохранение явного и неявного использования PLACE-8. Проверять прямые вызовы правил и движок.

Обновить запускаемые примеры, актуальные алгоритмы на английском и русском и общий документ области подключений. Устаревшую область в исторических спеках пометить как заменённую, сохранив историю решений. Нужны полный pytest и независимое ревью.

Реальные репозитории можно проверять локально только для чтения, показывая сводные результаты без значений и идентификаторов credentials. Нельзя выгружать, генерировать или менять данные в реальных репозиториях. Сохранить посторонние неотслеживаемые файлы.
