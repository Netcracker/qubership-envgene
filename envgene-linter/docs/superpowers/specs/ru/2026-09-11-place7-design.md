# envgene-linter: PLACE-7 (одна категория на ParameterSet)

Отбор проверяемых файлов определяется более поздним общим [правилом подключённости](../2026-09-11-connected-only-design.md).

Возможность сообщать о конфликтах без существующих файлов ниже сохранена как историческое решение. Теперь по общему правилу подключённости категории и позиции учитываются только для ссылок, выбирающих файлы в данном окружении. Для позиций сохраняются исходные индексы списков. См. [актуальный алгоритм](../../../algorithms/ru/place7.md); количество правил ниже относится к этому циклу.

Дата: 2026-09-11

Статус на момент проектирования: согласовано для реализации

Английская копия: [../2026-09-11-place7-design.md](../2026-09-11-place7-design.md)

## Контракт и область проверки

PLACE-7 SHOULD: ParameterSet указывается максимум в одном из массивов
`deployParameterSets`, `e2eParameterSets`,
`technicalConfigurationParameterSets`. Категорию задаёт массив привязки.
Если одинаковые значения нужны в нескольких категориях, создаются отдельные
ParameterSet.

Источник: раздел PLACE-7 в `docs/configuration-standard.md` локального
репозитория `qubership-envgene`, ветка `feature/modern-toolset`.

В этой реализации каждый `env_definition.yml` проверяется отдельно.
Используются соответствующие привязки экземпляра окружения из `envTemplate`:

| Категория | Поле привязки |
| --- | --- |
| deploy | `envSpecificParamsets` |
| e2e | `envSpecificE2EParamsets` |
| technical | `envSpecificTechnicalParamsets` |

Нарушение возникает, когда имя ссылки встречается минимум в двух категориях
одного окружения. Учитываются все цели привязки. Повторы внутри одной категории
допустимы: и в одном списке, и под разными целями.
Имена сравниваются точно в представлении `RepoIndex`, без изменения регистра
и удаления расширений. Категории разных окружений не объединяются.

## Примеры

Нарушение: `shared` привязан к deploy и technical в одном окружении.
Различие целей привязки не отменяет нарушение.

```yaml
envTemplate:
  envSpecificParamsets:
    cloud: [shared]
  envSpecificTechnicalParamsets:
    bss: [shared]
```

Допустимо: отдельные имена наборов для разных категорий.

```yaml
envTemplate:
  envSpecificParamsets:
    cloud: [shared-deploy]
  envSpecificTechnicalParamsets:
    bss: [shared-technical]
```

## Архитектура и алгоритм (первоначальная проверка только по привязкам)

Источник привязок — `RepoIndex`, как в PLACE-6. Повторный разбор YAML ради
самих привязок дублировал бы discovery. Файл перечитывается только для позиций.
Изменения discovery и вычисления Effective Set не требуются.

Новый модуль: `rules/place7.py`, функция `check(index: RepoIndex) -> list[Finding]`.

Для каждого окружения:

1. Перебрать категории в порядке deploy, e2e, technical. Через
   `env.bound_targets(category)` получить все цели и элементы списков ссылок.
2. Сгруппировать элементы по имени ссылки. Сохранить множество категорий
   и YAML-путь каждого элемента:
   `("envTemplate", category.binding_field, target, list_index)`.
3. Оставить имена, встречающиеся минимум в двух категориях. Если таких имён
   нет, замечаний нет и YAML перечитывать не нужно.
4. Один раз загрузить `{env.path}/Inventory/env_definition.yml` для позиций.
   При `YamlReadError` пропустить замечания этого окружения, как в PLACE-6.
5. Сформировать одно замечание на окружение и конфликтующее имя. В `locations`
   включить все вхождения ссылки, в том числе повторы внутри категории.
   Удалить одинаковые позиции и отсортировать по строке и колонке.
   Первую позицию использовать как основную. Для определения позиций применять
   существующий `LoadedYaml.position`, включая его поведение при недоступной позиции.

Сортировка замечаний: `(path.as_posix(), key, line)`.

В первоначальном проекте для проверки было достаточно привязок. Наличие и читаемость файла ParameterSet
не требуются. Содержимое, рендеринг Jinja, слой файла и разрешение ссылок
не определяют пересечение категорий. Отсутствующие и некорректные структуры
привязок обрабатываются существующим discovery.

## Замечание и отчёты

| Поле | Значение |
| --- | --- |
| `rule` | `PLACE-7` |
| `severity` | `Severity.WARNING` |
| `issue_type` | `Warning` |
| `action` | `Fix` |
| `path` / `line` / `column` | определение окружения; первое вхождение ссылки |
| `locations` | все вхождения конфликтующего имени в привязках |
| `key` | имя ссылки |
| `scope` | `<cluster>/<env>` |
| `related` | пусто |
| `message` | `ParameterSet {name!r} is bound to multiple categories: {categories}.` |
| `hint` | `Use a separate ParameterSet for each category, even when the parameter values are identical.` |

`{name!r}` означает имя ссылки в представлении Python `repr`, включая кавычки.
`categories` — названия участвующих категорий через запятую с пробелом,
в фиксированном порядке `deploy`, `e2e`, `technical`.

Описание в каталоге: `One category per ParameterSet`.
Движок вызывает `check_place7(index)` после PLACE-6 и перед NAME-1.
Порядок правил в консоли:
`PLACE-1`, `PLACE-2`, `PLACE-3`, `PLACE-4`, `PLACE-6`, `PLACE-7`,
`NAME-1`, `NAME-2`, `NAME-3`, `NAME-4`.

При отсутствии замечаний консоль содержит блок `PLACE-7\nNo findings`.
Существующий HTML-рендерер выводит заголовок
`PLACE-7: One category per ParameterSet`, все позиции и метки Warning / Fix.
Замечания сохраняют код выхода 0. Автоисправлений и новых опций CLI нет.
Другие правила, включая NAME-4, сохраняют поведение; замечания разных правил
не подавляются.

## Проверки и документация

Тесты покрывают:

- Каждую пару категорий и все три; одно замечание на имя и окружение.
- Одинаковые и разные цели привязки в разных категориях.
- Повторы в одной категории, включая разные цели: замечаний нет.
- Раздельные имена, отсутствующие привязки и пустые списки: замечаний нет.
- Несколько конфликтующих имён и окружений; отсутствие объединения между окружениями.
- Точное сравнение имён и конфликты без файлов ParameterSet.
- Все позиции элементов списков, их порядок, устранение одинаковых позиций,
  основную позицию, точные message и hint, Warning / Fix и порядок замечаний.
- Ошибку повторного чтения определения окружения: без падения и замечаний этого окружения.
- Интеграцию с движком, порядок и пустые блоки консоли, позиции и метки HTML,
  код выхода 0 при нарушениях.
