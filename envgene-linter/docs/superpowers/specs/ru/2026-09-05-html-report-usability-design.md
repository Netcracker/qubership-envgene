Три спецификации HTML описывают последовательные этапы одной даты: [первый отчёт](2026-09-05-html-report-design.md) → [переделка](2026-09-05-html-report-redesign-design.md) → [удобство отчёта](2026-09-05-html-report-usability-design.md). Это последний из трёх этапов HTML. Он заменяет требования переделки к заголовкам, раскрытию секций, размеру меток и выводу позиций. Последующие спецификации правил расширяют каталог и `RULE_ORDER`. Проверки ключей PLACE-3 ниже — исторические: [PLACE-4](2026-09-07-place4-design.md) позже заменяет их проверкой контрактных ключей в ParameterSet; PLACE-3 сохраняет проверку размещения файлов паспорта.

Продолжение [переделки HTML-отчёта](2026-09-05-html-report-redesign-design.md). Поля карточки, чипы, `--html`, gitignore и «без JS» остаются. Меняем вид секции правила и список всех копий ключа.

## Зачем

В HTML и в консоли должны быть **все файлы**, где ключ совпал. Секция правила — закрытый `<details>` с заголовком `PLACE-1: Same value belongs on a higher layer`. Метки мелкие, читать надо значения.

## Простыми словами

PLACE-1 пишет «одинаково в трёх окружениях». FILE должен показать три строки `path:line:column`, не одного представителя. Клик по заголовку открывает карточки. JavaScript нет: `<details>` / `<summary>`.

## Что не делаем

- Раскрытие секций с помощью JavaScript
- Менять условия срабатывания PLACE-*
- Autofix / JSON
- Снова переписывать фразы ISSUE / FIX SUGGESTION
- Обновлять документы алгоритмов

## `Finding.locations`

Новое поле: `locations: tuple[Location, ...] = ()`.

```python
@dataclass(frozen=True)
class Location:
    path: Path
    line: int
    column: int
```

Позиция указывает исходный файл, строку и столбец ключа; нумерация начинается с 1. Основная позиция хранится в `Finding.path`, `Finding.line` и `Finding.column`. Пустой `locations` означает «показать только основную позицию», а не «не показывать файлы».

Правила заполняют `locations` по исходным файлам, которые предоставили совпавшие значения (owners). Сохраняем порядок источников, переданный правилом; из повторов `(path, line, column)` оставляем первое вхождение. HTML и консоль повторно не сортируют эти позиции. «Совпавшие» значения — равные в том сравнении, которое породило замечание.

| Правило | Случай | Заполняем |
| --- | --- | --- |
| PLACE-1 | env → cluster | исходный файл и `position()` каждого окружения с совпавшим значением |
| PLACE-1 | cluster → repository | исходный файл и `position()` каждого кластера с совпавшим значением |
| PLACE-3 | ключ контракта в нескольких env | исходная позиция каждого окружения группы (исторический случай PLACE-3) |
| PLACE-2 | повтор значения нижнего слоя | пусто |
| PLACE-3 | паспорт не там / ключ на repository | пусто |

`related` не меняем и на страницу не выводим.

Основные `path` / `line` / `column` сохраняют позицию первого источника. Если `locations` не пустой, основная позиция тоже должна быть в списке.

## FILE и консоль

Общий выбор позиций для HTML и консоли (`Finding.file_locations()`): если `locations` не пустой, берём его; иначе создаём один `Location` из основных полей.

**FILE в HTML:** по строке на позицию, моноширинно: `{относительный/путь}:{строка}:{столбец}`.

Например, две совпавшие копии дают одну карточку, в которой FILE содержит:

```text
environments/cluster-01/env-a/Inventory/parameters/app.yml:4:3
environments/cluster-01/env-b/Inventory/parameters/app.yml:7:3
```

Строки ISSUE, TYPE, ACTION и FIX SUGGESTION выводятся один раз для этого замечания.

**Консоль:** вместо одной `{path}:{line}` — по строке `{path}:{line}:{column}` на каждую копию. Дальше severity, message, hint как сейчас. Столбец добавляется и к замечанию с одной позицией, в том числе без `--html`. Пустые блоки правил не меняем (`PLACE-2\nNo findings`).

## Страница

### Заголовок

Одна строка:

```text
PLACE-1: Same value belongs on a higher layer
```

`{id}: {description}` если правило в каталоге. Неизвестное — только id, без двоеточия.

Шрифт Georgia, как у нынешнего `h2.rule-id`.

### Сворачивание секций

Каждое правило с замечаниями — `<details>` **без** `open` (закрыто). `<summary>` — строка заголовка. Карточки внутри.

Без JS. Без `<script>`.

Вокруг `<details>`: тонкая рамка 1px `#e2e2e2`, лёгкое скругление, небольшой отступ — открытая секция одним блоком, не сливается со следующей.

Ноль замечаний: заголовок + `No findings`. Без `<details>`.

### Метки

Метки остаются: `FILE`, `ISSUE`, `TYPE`, `ACTION`, `FIX SUGGESTION`. Мельче и бледнее значений: около `0.7rem`, не жирные, цвет `#666`. Колонка меток около `6.5rem`. Значения как сейчас.

## Тесты

- PLACE-1 на двух env: `len(locations) == 2`; в FILE оба пути и оба `:line:column`; в консоли оба `path:line:column`
- PLACE-2: `locations == ()`; FILE — одна основная позиция
- Заголовок `PLACE-1: Same value belongs on a higher layer` в одном элементе (summary)
- В HTML есть `<details>` и `<summary>`, у этих details нет `open`
- Есть CSS-класс секции или стиль `details`, задающий рамку
- Метки на месте; пиксели CSS не проверяем
- Escape / no-script / gitignore остаются
