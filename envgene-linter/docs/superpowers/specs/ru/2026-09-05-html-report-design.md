## Порядок чтения и последующие изменения

Три спецификации HTML описывают последовательные этапы одной даты: [первый отчёт](2026-09-05-html-report-design.md) → [переделка](2026-09-05-html-report-redesign-design.md) → [удобство отчёта](2026-09-05-html-report-usability-design.md). Следующий этап заменяет явно изменённые требования предыдущего; остальные сохраняются. Строки статуса отражают первоначальное состояние согласования.

Это первый этап, сохранённый как история решений. Переделка заменяет группировку по файлам, заголовок, счётчики, поля карточки и решение не менять `.gitignore`. Этап удобства добавляет свёрнутые секции правил и все позиции замечания, включая столбцы в консоли. Требования к странице и тестам ниже нужно читать с учётом этих изменений.

## Зачем

`envgene-linter check <repo> --html` печатает консоль как сейчас **и** пишет одну HTML-страницу с теми же замечаниями, сгруппированными по файлу. Замечание (`Finding`) — одна обнаруженная проблема; она может относиться к одному или нескольким исходным файлам.

Без `--html` ничего не меняется: только консоль.

## Простыми словами

Консоль — для терминала и CI. HTML — открыть в браузере: заголовок на каждый проблемный файл, под ним карточки (правило + текст).

Автоматических исправлений и готовых фрагментов YAML с правками нет. JSON-отчёта нет. Сообщения о пропущенных шаблонах Jinja и нечитаемом YAML остаются в stderr и не попадают на страницу.

## Что не делаем в этом цикле

- Autofix / подсказки правок
- JSON, `--strict`, `--rules`, baseline, `[EXCEPTION …]`
- Править `.gitignore` instance-репо
- Менять поиск файлов, Effective Set (значения параметров после объединения слоёв), PLACE-1/2/3
- Менять формирование консольного отчёта

## CLI

```text
envgene-linter check <repo> --html
```

`--html` — флаг, без пути. Файл всегда:

```text
<корень-instance-репо>/envgene-linter-report.html
```

Корень — каталог с `environments/` (тот же аргумент `check`). Каждый `--html` перезаписывает файл.

После успешной записи одна строка в **stderr**:

```text
Wrote HTML report to envgene-linter-report.html
```

Первоначальный дизайн разрешал относительный или абсолютный путь в этом сообщении. В переделке закреплён точный текст выше.

Замечания консоли — **stdout**, те же байты, что без флага; обычные сообщения о пропусках идут в stderr.

## Если файл не записался

Если есть `--html` и записать не вышло:

1. Консоль уже напечатана (сначала печать, потом запись).
2. Ошибка в stderr, например `cannot write HTML report <path>: <reason>`.
3. Выход **2**.

Без `--html` коды те же: `0` на warning / нет замечаний, `2` если нет `environments/` или неверных аргументах CLI.

## Страница

Один HTML. CSS внутри. Без JavaScript. Без `<script>`. `lang="en"`. Все поля и пути через `html.escape`, чтобы `<` в message не стал тегом.

### Шапка

- Заголовок: `envgene-linter report`
- Строка-итог: число findings по правилам в порядке `PLACE-1`, `PLACE-2`, `PLACE-3`, например `PLACE-1: 1, PLACE-2: 0, PLACE-3: 2`
- Заметка: сгенерировано `envgene-linter check --html`; не коммить; файл перезаписывается каждый запуск

### Тело

Только файлы, где есть хотя бы одно замечание.

1. Файлы по относительному пути от корня репо (разделитель `/`).
2. Один заголовок на файл (относительный путь, моноширинный).
3. Под ним карточки этого файла, в порядке правил консоли (`PLACE-1`, потом `PLACE-2`, потом `PLACE-3`). Одно правило — порядок как в engine.

На карточке:

| Поле | Откуда |
| --- | --- |
| rule | `Finding.rule` |
| severity | `Finding.severity` (`warning`) |
| line | `Finding.line` |
| message | `Finding.message` |
| hint | `Finding.hint` |

`scope` и `related` не печатаем (консоль тоже не печатает).

Ноль замечаний: файл всё равно пишем. Шапка + нули в итоге + одно `No findings` (без заголовков файлов).

### Карточка (смысл, не пиксели)

```
<относительный/путь.yml>

  PLACE-3 · warning · line 4
  <message>
  <hint>
```

Карточка визуально отделена (например полоска слева). Светлая тема, системный шрифт, без внешних картинок.

## Что меняем в коде

| Файл | Зачем |
| --- | --- |
| `src/envgene_linter/html_report.py` | `REPORT_FILENAME`, `report_path(root)`, `render_html(findings, root)` |
| `src/envgene_linter/cli.py` | флаг `--html`; запись после консоли |
| `tests/test_html_report.py` | Содержимое страницы |
| `tests/test_cli.py` | Флаг пишет / не пишет файл; ошибка записи |

`report.py` остаётся консолью. `engine.py` не трогаем (`CheckResult.findings` и `skipped` остаются).

`render_html` берёт список findings и корень репо (для относительных путей). Планов правок нет.

## Тесты

Добавляем тесты HTML и CLI для этого этапа:

- `--html` создаёт `envgene-linter-report.html` в корне репо; без флага новый файл не создаётся (существующий отчёт остаётся без изменений)
- два замечания в одном файле → один заголовок, две карточки
- замечания в двух файлах → два заголовка
- ноль замечаний → файл есть, внутри `No findings`, без заголовков файлов
- `<` в message → в HTML `&lt;`, не тег
- в HTML нет `<script`
- с `--html` stdout тот же, что без флага
- не записали → stderr про путь, выход 2 (stdout уже с консолью)

Лабы PLACE-* не добавляем.

## Документы алгоритма

Нового документа алгоритма нет: это только представление. Контракт этого этапа — английская спецификация с учётом последующих изменений по ссылкам выше; русский текст — её перевод для читателя.
