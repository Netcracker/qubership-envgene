# PLACE-8: проверка подключённых или используемых пустых сущностей

Отбор проверяемых файлов определяется более поздним общим [правилом подключённости](../2026-09-11-connected-only-design.md).

Общее правило подключённости переиспользует описанный ниже поиск без изменения результатов PLACE-8. Архитектура и количество правил относятся к этому циклу; см. [актуальный алгоритм](../../../algorithms/ru/place8.md).

Дата: 2026-09-11

Статус на момент проектирования: согласовано и реализовано.

Английская копия: [../2026-09-11-place8-design.md](../2026-09-11-place8-design.md).

## Область реализации

Эта реализация PLACE-8 проверяет пустые ParameterSet, Resource Profile Override
и файлы credentials с видимой привязкой или известным использованием генератором.
Правило не определяет, намеренно ли сущность оставлена пустой: замечание имеет
статус Information / Review.
Размер, количество приложений, названия сервисов и префиксы ключей не служат
основанием для дополнительных выводов о содержимом файла.

Для всех трёх типов согласовано:

- Пустой файл с видимой привязкой или известным использованием генератором: одно Information / Review на файл.
- Файл без видимой привязки и известного использования: пропускается.
- Непустой файл: замечания PLACE-8 нет.

Привязки из шаблонов не исследуются: файлы, использование которых известно
только из шаблонов, пропускаются. Рекомендация — проверить, намеренно ли сущность оставлена
пустой.

Источник поведения поиска: локальный `qubership-envgene`, ветка
`feature/modern-toolset`: `get_env_specific_resource_profiles` в
`scripts/build_env/resource_profiles.py`, `findSharedCredentials` в
`scripts/build_env/create_credentials.py`, `find_yaml_file` в
`modules/envgene/envgenehelper/yaml_helper.py`.
Для ParameterSet используется существующий `effective.resolve_reference` линтера.

## Discovery и модель

Расширить существующие `RepoIndex` и discovery. Новые поля имеют пустые значения
по умолчанию, сохраняя совместимость конструкторов. Использовать `NamedEntityFile`
как запись загруженного файла в отдельных списках `RepoIndex.resource_profiles`
и `RepoIndex.credential_files`. В `named_entities`, которые проверяет NAME-2,
эти записи не добавлять.

В `EnvModel` добавить `resource_profile_bindings: dict[str, str]` и
`shared_credential_bindings: list[str]`. Источники в `envTemplate`:

| Тип | Привязка |
| --- | --- |
| ParameterSet | существующие карты deploy, e2e, technical `envSpecific*Paramsets` |
| Resource Profile Override | `envSpecificResourceProfiles`: цель → имя ссылки |
| Общие credentials | `sharedMasterCredentialFiles`: список имён ссылок |

Новые имена ссылок сохранять точно, без смены регистра и удаления расширений.
Некорректные контейнеры новых привязок и нестроковые элементы пропускать.
Существующее поведение discovery для ParameterSet сохраняется.

Проверять базовые каталоги `environments/`, каталоги существующих кластеров и
`Inventory/` найденных окружений. В каждом базовом каталоге:

- Профили: `resource_profiles`, `rp_override`, `Profiles`; затем `parameters`
  как старый вариант расположения, поддерживаемый генератором.
- Credentials: `credentials`, `Credentials`, `shared-credentials`.

В каталогах профилей и credentials искать `.yml` и `.yaml` рекурсивно.
`.yml.j2` и `.yaml.j2` учитывать как пропущенные шаблоны, без рендеринга.
Исключать `.git` и сгенерированные файлы окружений вне Inventory, включая
`<env>/Profiles` и `<env>/Credentials`. Глубина и расположение поиска
ParameterSet остаются прежними. Один и тот же файл определяется по пути после раскрытия символических ссылок;
по симлинкам за пределы instance-репозитория не переходить.

Новые сообщения об ошибках чтения содержат только путь и общую причину,
например `cannot parse YAML; PLACE-8 skipped`. Фрагменты YAML, значения,
идентификаторы credentials и секреты в замечания и сообщения не включать.


Известное неявное использование: генератор читает точный путь
`Inventory/credentials/inventory_generation_creds.yml` каждого найденного окружения
через `INV_GEN_CREDS_PATH` в `envgenehelper/env_helper.py:Environment`, даже без явной
привязки. Пустой существующий файл даёт Information / Review. Отсутствующий файл
допустим (`allow_default=True`) и замечания не даёт. Одноимённые файлы репозитория
и кластера не считаются используемыми автоматически. Другие способы неявного
использования и привязки из шаблонов не предполагаются.

## Видимые привязки

Собрать множество подключённых физических путей по всем найденным окружениям.
Ссылка в чужом кластере не делает одноимённый файл подключённым.
Общий файл считается подключённым, если его выбирает хотя бы одна видимая привязка.

Для ParameterSet вызвать `resolve_reference(index, env, reference)` для всех
категорий и целей. Учитывать все сохранившиеся после подготовки входных файлов (staging) файлы, включая
переопределения окружения. Файл репозитория, замещённый одноимённым файлом
кластера, не становится подключённым только из-за совпадения имени без расширения (`stem`).

Для профилей и credentials порядок базовых каталогов: Inventory окружения → кластер →
`environments`. Внутри каждого базового каталога — порядок каталогов, указанный выше.
Рекурсивно искать точное имя файла без расширения. Остановиться на первом каталоге с совпадением.
Нечитаемый совпавший YAML занимает своё место; к следующим каталогам не переходить.

При нескольких совпадениях внутри одного каталога генератор выбирает файл по
порядку обхода файловой системы. Этот порядок не является устойчивым критерием.
Поэтому все кандидаты такого каталога считаются потенциально подключёнными
и проверяются на пустоту. Линтер не выбирает один файл произвольно; каталоги с более низким приоритетом не рассматриваются.

Множество подключённых путей общее для типов: профиль, выбранный из старого
каталога `parameters/`, не должен получить второе замечание как пустой ParameterSet.

## Тип сущности в старом каталоге parameters

Классификация определяет способ проверки кандидата, но не доказывает его использование. Если файл не выбран и не используется, замечания по нему не выдаются, даже когда тип распознан.

В специализированных каталогах тип определяется каталогом. В `parameters/`:

- Путь, выбранный привязкой профиля, является кандидатом профиля.
- YAML-карта с элементами `applications`, содержащими `services`, также
  является кандидатом профиля, даже без привязки.
- Остальные существующие кандидаты ParameterSet сохраняют свой тип.

Для распознаваемых профилей применять определение пустоты профиля. Смешанную
или нераспознаваемую структуру пропускать, а не считать пустой.
Пустую непривязанную карту в `parameters/` без признаков профиля считать
ParameterSet по расположению. На физический файл выдавать максимум одно замечание.
Эта классификация применяется только в PLACE-8 и не меняет другие правила.

## Пустое, непустое и неизвестное содержимое

Проверять структуру, а не логическую истинность отдельных значений. Пустая
корневая карта, документ из пробелов/комментариев и корневой null считаются пустыми.
Остальные некартовые корни пропускаются как неизвестная структура. Пустой
YAML-список не является корректной картой сущности и не считается пустой сущностью.

**ParameterSet:** нет записей в `parameters` и ни в одном
`applications[].parameters`. Отсутствующие контейнеры считаются отсутствующим
содержимым; имена приложений без параметров содержимого не добавляют.
Ключ параметра считается содержимым при любом значении, включая null,
`""`, false, 0, пустую карту или список. `name`, `version` и другие метаданные
не считаются параметрами. Неправильные типы контейнеров и некорректные элементы
приложений делают пустоту неизвестной.

**Resource Profile Override:** нет записей параметров ни в одном списке
`applications[].services[].parameters`. Отсутствующие и пустые контейнеры не
добавляют записей. Имена приложений/сервисов и метаданные не являются параметрами.
Любая запись параметра исключает замечание о пустоте, даже с незаполненным
значением. Неправильные контейнеры и некорректные элементы приложений/сервисов
считаются неизвестной структурой.

В этих структурных проверках элемент приложения/сервиса должен быть картой;
проверка обязательного имени и других требований схемы не входит в PLACE-8.
Явный null в контейнере имеет неправильный тип и считается неизвестной
структурой, в отличие от отсутствующего контейнера. Корневую карту можно
признать пустой только с ключами `name`, `version`, `description`, `parameters`,
`applications` для ParameterSet или `name`, `version`, `description`, `baseline`,
`applications` для профиля. Другие корневые ключи делают иначе пустого кандидата
неизвестным. Незнакомый или зашифрованный документ не принимается за пустые метаданные.

**Credentials:** пустая корневая карта или пустой документ. Любая верхнеуровневая
запись исключает замечание о пустоте, даже с незаполненными полями credential.
Расшифровка и проверка значений не выполняются; зашифрованная карта не считается пустой.

Нечитаемый YAML, Jinja и неизвестная структура пропускаются. Это не проверка схемы.

## Правило и отчёт

Создать `rules/place8.py:check(index: RepoIndex) -> list[Finding]`.
Собрать подключённые пути, классифицировать и устранить дубли кандидатов,
сообщить только об известных пустых файлах из множества подключённых или используемых.
Вычислять Effective Set не требуется.

| Поле | Значение |
| --- | --- |
| `rule` | `PLACE-8` |
| `severity` | `Severity.INFORMATION` |
| `issue_type` | `IssueType.INFORMATION` |
| `action` | `Action.REVIEW` |
| `path` | файл пустой сущности |
| `line`, `column` | `1`, `1`: замечание ко всему файлу |
| `locations` | эта одна позиция |
| `key` | stem файла |
| `scope` | `repository`, имя каталога кластера или `<cluster>/<env>` |
| `related` | пусто |
| `message` | `{kind} {filename!r} is empty but is referenced or used by the generator.` |
| `hint` | `Review whether this empty file is intentional. If not, populate it or remove its reference or usage.` |

`{filename!r}` — имя файла в представлении Python `repr`, включая кавычки.
`kind`: `ParameterSet`, `Resource Profile Override` или `Credentials file`.
Описание в каталоге: `Referenced or used entities are empty`.
Сортировка: `(path.as_posix(), key, line)`.

Включить PLACE-8 после PLACE-7 и перед NAME-1 в движке, каталоге и порядке
отчёта. Консоль печатает все одиннадцать заголовков, пустой блок —
`PLACE-8\nNo findings`. HTML использует существующий рендерер и метки
Information / Review. Код выхода при замечаниях — 0. Автоисправлений и новых опций CLI нет.

## Проверки

Для каждого типа: пустой без привязки, пустой с привязкой, непустой.
Покрыть параметры верхнего уровня и приложений, одни метаданные, пустые
документы, false/null/0/пустые строки, некорректную структуру, Jinja,
зашифрованные карты и сообщения ошибок без содержимого YAML.

Для поиска: каждый уровень, старые имена каталогов, вложенные файлы, точные
имена, чужой кластер, затенение, несколько окружений, неоднозначные совпадения,
нечитаемый выбранный файл и профили в `parameters/` без повторных замечаний.
Проверить исключение сгенерированных файлов и симлинков за пределы репозитория.

Интеграционные тесты закрепляют поля и тексты замечания, сортировку, порядок
одиннадцати правил, HTML и код выхода. Полный набор тестов защищает discovery
и существующие правила. Добавить искусственные ok/not-ok примеры и алгоритм
на английском и русском.

Реальные репозитории `/home/andy-/test_data` исследуются только локально и без
изменений. Не загружать их в сеть, не запускать на них генерацию, не копировать
реальные файлы в тесты или коммитируемую документацию и не выводить секреты.
Примеры для тестов и документации должны быть искусственными.
