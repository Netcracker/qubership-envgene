# PLACE-10: каждая подключённая сущность находится в каталоге своего типа

Статус: реализовано. Спецификация описывает согласованную самостоятельную проверку каталога.
Английская версия: [2026-09-11-place10-design.md](../2026-09-11-place10-design.md).

## Назначение и область проверки

PLACE-10 проверяет **все пять типов из таблицы**, а не только ParameterSet. Проверяются существующие файлы, использование которых подтверждено локальной ссылкой или известным поведением генератора. Тип произвольного YAML по содержимому не определяется.

| Тип подключённой сущности | Требуемый каталог |
| --- | --- |
| ParameterSet | `parameters/` |
| Resource Profile Override | `resource_profiles/` |
| Shared Template Variables | `shared-template-variables/` |
| Shared credentials | `credentials/` |
| Cloud Passport | `cloud-passport/` |

Физический файл — файл, полученный после разрешения символьных ссылок. Если один физический файл используется как два типа сущностей, он проверяется один раз для каждого типа. В замечании сохраняется соответствующий путь подключения — путь, через который файл был выбран.

Неиспользуемые файлы, неразрешившиеся ссылки, неоднозначные невыбранные паспорта, внешние файлы и файлы внутри `.git` не участвуют. Пустой или некорректный YAML не отменяет проверку каталога, если использование подтверждено: читать содержимое или секреты для этой проверки не требуется.

## Проверка каталога

1. Взять уже выбранные пути ParameterSet, профилей, shared credentials и паспортов. Для Shared Template Variables установить использование по алгоритму ниже.
2. По физическому пути определить фактический уровень файла. Среди известных баз, содержащих файл, выбрать самую глубокую: `Inventory/` окружения, каталог кластера или корневой `environments/`.
3. Первый компонент пути ниже базы должен точно совпадать с каталогом типа из таблицы. Вложенные каталоги **внутри** требуемого каталога допустимы.
4. Если выбранный физический файл находится внутри репозитория, но вне этих баз, сообщить о неправильном размещении. Предлагаемый путь — `environments/<каталог-типа>/`.
5. Выдать одно замечание на пару «физический файл, тип». Отсортировать замечания по пути, ключу и строке.

Проверка не задаёт обязательный уровень, имя файла или глубину вложенности внутри правильного каталога. Другие правила могут выдавать свои замечания на тот же файл: PLACE-10 не подавляет пересечения, в том числе с PLACE-9.

Примеры:

- `Inventory/parameters/service-deploy.yml` — правильно для подключённого ParameterSet.
- `Inventory/resource_profiles/team/profile.yml` — правильно для подключённого Resource Profile Override.
- `Inventory/parameters/resource_profiles/profile.yml` — неправильно для такого профиля: первый каталог ниже `Inventory/` — `parameters/`.
- Неподключённая копия в любом из этих каталогов не даёт замечания PLACE-10.

## Как устанавливается использование Shared Template Variables

Прочитать строковые элементы списка `envTemplate.sharedTemplateVariables`. Неверные контейнеры, нестроковые элементы и динамические ссылки Jinja не выбирают файлы.

Для каждой буквальной ссылки использовать поиск локального генератора `process_additional_template_parameters`. Проверять каталоги по порядку:

1. `<окружение>/Inventory/configuration/`
2. `<окружение>/Inventory/configurations/`
3. `<кластер>/configuration/`
4. `<кластер>/configurations/`
5. `environments/configuration/`
6. `environments/configurations/`
7. `<окружение>/Inventory/`

Рекурсивно искать файл `.yml` или `.yaml`, чьё имя без расширения (stem) точно совпадает со ссылкой. Выбирается первый совпавший файл в первом подходящем каталоге. Сохраняется порядок обхода `os.walk`, используемый генератором: файлы не сортируются, одноимённые входы не объединяются.

Не обходить символьные ссылки на каталоги, включая ссылки среди родителей корня поиска, и каталоги `.git`. Исключать внешние пути. Если встретившийся совпавший файл небезопасен, он занимает место в поиске: пропустить его без выбора файла меньшего приоритета. Каталог, исключённый до обхода, не просматривается.

Содержимое файлов для установления использования не разбирается. Добавить пустые по умолчанию поля `EnvModel.shared_template_variable_bindings` и `Connections.shared_template_variables`, сохранив прежние позиционные аргументы конструкторов. Выбранные файлы входят в общий набор подключений и наборы окружений.

### Стандарт и поиск генератора

Стандарт требует `shared-template-variables/`, а локальный генератор ищет в перечисленных выше старых каталогах `configuration/` и `configurations/`. Поэтому используемый файл `environments/configuration/variables/ci-global-vars.yml` вызывает PLACE-10, хотя генератор умеет его загрузить.

Замечание сообщает о несоответствии стандарту каталогов, а не о сбое генерации. Нельзя молча исключать старые пути из проверки или менять поиск генератора. Каталог `Inventory/shared-template-variables/` окружения доступен через заключительный рекурсивный поиск; поддержку других неразрешившихся канонических путей не предполагаем.

## Замечания и отчёт

PLACE-10 — требование MUST. Замечания используют существующие **Warning / Fix** и сохраняют код завершения CLI `0`.

Замечание содержит тип сущности, выбранное имя файла и ожидаемый каталог. Подсказка указывает ожидаемый путь на фактическом уровне. Позиция одна: строка 1, столбец 1. Поле `scope` обозначает репозиторий, кластер или окружение, `key` — имя файла без расширения.

Описание каталога: `Entities belong in their type directories`. PLACE-10 добавляет тринадцатый заголовок консоли после PLACE-9 и перед NAME-1. Консоль показывает заголовки и без замечаний; HTML содержит только разделы с замечаниями. Новых флагов, автоматического изменения файлов, сетевых обращений и записи в реальные репозитории нет.

## Проверка реализации

Использовать синтетические примеры:

- Правильные и неправильные каталоги всех пяти типов с реальными привязками.
- Неправильно размещённый ParameterSet, выбранный через символьную ссылку внутри репозитория.
- Допустимая вложенность и правильное имя каталога внутри неправильного каталога.
- Старые каталоги профилей, shared credentials и паспортов во множественном числе; независимые замечания других правил.
- Неподключённые, отсутствующие, Jinja, внешние и `.git` входы; выбранные некорректные файлы.
- Несколько путей к одному физическому файлу и использование одного файла как нескольких типов.
- Приоритет поиска Shared Template Variables, точное имя, небезопасные совпадения и исключённые родительские каталоги.
- Совместимость конструкторов, прямой вызов правила, движок, консоль, HTML и каталог правил.
