# envgene-linter: PLACE-2

Отбор проверяемых файлов определяется более поздним общим [правилом подключённости](../2026-09-11-connected-only-design.md).

Ниже сохранены решения этого цикла и его порядок отчёта. Актуальный [PLACE-2](../../../algorithms/ru/place2.md) сравнивает только выбранные физические файлы; проекция не должна возвращать файл репозитория, затенённый файлом кластера.

Дата: 2026-09-02  
Статус на момент проектирования: принят\
Английская версия: [../2026-09-02-place2-design.md](../2026-09-02-place2-design.md)

## Зачем

Термины: `env` — окружение; привязка — ссылка из `env_definition.yml` на набор параметров; `scope` — область «цель × категория», при необходимости отдельно для приложения. Effective Set — итоговые значения после объединения ParameterSet; `discovery` — обнаружение файлов и чтение привязок.

`envgene-linter check <repo>` печатает сначала PLACE-1, потом PLACE-2.

PLACE-2 (SHOULD): если более конкретный слой повторяет значение, уже заданное общими слоями, это лишний повтор. Нужно убрать ключ из более конкретного слоя или изменить значение, если требовалось переопределение.

## Простыми словами

Три слоя, как в PLACE-1: репозиторий (`environments/parameters/`) → кластер → env.

В расчёт идут только ParameterSet’ы, которые названы в `env_definition`. Остальные файлы правило не видит.

PLACE-1 говорит: «одно и то же во всех env — подними выше».  
PLACE-2 говорит: «окружение или кластер повторили унаследованное значение — удали копию».

Один ключ не получает оба правила: PLACE-1 исключает такие повторы.

## Что не делаем в этом цикле

- Template, passport, Jinja
- `--rules`, JSON/HTML, baseline, `[EXCEPTION …]`, autofix
- Другие правила (PLACE-3 и дальше)

## Как работает правило

Берём те же три проекции Effective Set, что и PLACE-1: `full`, `lower` (без env), `site` (только репозиторий).

Для каждого ключа, **заданного** более конкретным слоем (окружением или кластером), сравниваем ту же область и путь ключа в проекции общих слоёв:

1. В общей проекции этого ключа нет → замечания нет (это новое, не повтор).
2. В общей проекции другое значение → замечания нет (настоящая правка).
3. В общей проекции то же значение → warning PLACE-2.

Два сравнения:

- **Окружение относительно общих слоёв.** Env написал `LOG_LEVEL: info`, кластер (или репозиторий) уже дал `LOG_LEVEL: info` → замечание.
- **Кластер относительно репозитория.** Кластер написал то же, что уже есть в `environments/parameters/` → замечание.

Кластерный файл один, окружений несколько. Замечание по кластерному повтору выдаём **один раз**, не по разу на каждый env.

### Примеры

Окружение подключает `shared` и `env-deploy` через `envSpecificParamsets.cloud`. Ниже два отдельных файла ParameterSet; окружение повторяет значение кластера:

```yaml
# environments/cluster-01/parameters/shared.yml
name: shared
parameters:
  LOG_LEVEL: info
  REPLICA_COUNT: 2
```

```yaml
# environments/cluster-01/env-01/Inventory/parameters/env-deploy.yml
name: env-deploy
parameters:
  LOG_LEVEL: info      # повтор
  REPLICA_COUNT: 3     # настоящее переопределение
```

Одно замечание: `LOG_LEVEL`. Подсказка: убери ключ здесь или измени значение.

Хорошо: в env только `REPLICA_COUNT: 3`. Замечаний нет.

Сравнение кластера с репозиторием работает так же. Выдаётся одно замечание на исходный файл и конечный ключ, даже если повтор видят несколько окружений или областей. Разные повторённые ключи в одном файле дают отдельные замечания.

## Отчёт

Тот же формат, что у PLACE-1:

```
PLACE-1
…

PLACE-2
<path>:<строка>
warning
Key LOG_LEVEL at the environment layer repeats the value already supplied by the cluster layer
Remove LOG_LEVEL here, or change the value if a genuine difference was intended
```

Нет замечаний у правила: свой заголовок и `No findings`. Оба заголовка печатаем всегда, даже если одно из правил молчит.

Коды выхода не меняем: 0 при warning, 2 если нет `environments/`.

## Тесты

Пишем вместе с правилом:

- окружение повторяет кластер → одно замечание
- значение другое → замечаний нет
- ключа в общих слоях нет → замечаний нет
- кластер копирует репозиторий → одно замечание
- два окружения видят один кластерный повтор → одно замечание, не два
- примеры: `testdata/place2/ok` и `testdata/place2/not-ok`
