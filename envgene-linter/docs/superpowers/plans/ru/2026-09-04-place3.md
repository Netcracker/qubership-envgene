# План: PLACE-3

Английская копия (по ней пишут код): [../2026-09-04-place3.md](../2026-09-04-place3.md)

**Что получим:** `check` печатает PLACE-1, потом PLACE-2, потом PLACE-3.

**Идея:** discovery видит файлы passport и `inventory.cloudPassport`. Новый `passport.py` собирает каталог ключей (таблица EnvGene + ключи из резолвленного файла). Правило ловит файл не на кластере, ключ контракта в `environments/parameters/`, и один и тот же ключ в двух+ env. PLACE-1 эти ключи больше не поднимает. В Effective Set passport не мешаем.

## Шесть задач

### 1. Найти passport и собрать каталог

`model.py`, `discovery.py`, новый `passport.py`, фикстура `repo.passport(...)` и `cloud_passport=` у `env`.

Тесты: явный резолв, auto `passport.yml`, нет файла → только таблица, два файла с одним именем → не резолвим, ключ из файла кластера попадает в каталог кластера.

### 2. Само правило

Новый `rules/place3.py`:

- passport в `environments/cloud-passport/` → warning
- passport в `Inventory/cloud-passport/` у env → warning
- passport в `environments/<cluster>/cloud-passport/` → тишина
- `DBAAS_AGGREGATOR_ADDRESS` в `environments/parameters/` → warning
- свободный ключ из passport кластера на репозитории → warning
- два env, одно значение, снизу нет → один PLACE-3
- один env / разные значения → тишина
- повтор как у PLACE-2 (уже есть на кластере в ParameterSet) → PLACE-3 молчит

### 3. PLACE-1 не трогает каталог

Два env с одинаковым `DBAAS_AGGREGATOR_ADDRESS` без catalogs — как раньше, PLACE-1. С catalogs — пусто (это PLACE-3).

`MONITORING_URL` по-прежнему PLACE-1: его нет в таблице.

### 4. Отчёт и `check`

Всегда три заголовка. Пустой прогон:

```
PLACE-1
No findings

PLACE-2
No findings

PLACE-3
No findings
```

`run_check` вызывает PLACE-3 и передаёт catalogs в PLACE-1.

### 5. Живые деревья

`testdata/place3/not-ok` — два env, оба пишут один и тот же `DBAAS_AGGREGATOR_ADDRESS`.  
`testdata/place3/ok` — значения разные (настоящий override). Файл passport, если есть, лежит на кластере.
