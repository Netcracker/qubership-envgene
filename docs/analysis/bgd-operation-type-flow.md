## Краткое описание

BG Plugin запускает Instance pipeline и передаёт Environment и тип операции.

Instance pipeline маршрутизирует вызов. Для `BGD-*` операций EnvGene определяет текущее состояние
BG Domain, проверяет допустимость операции, выполняет внутреннюю обработку и обновляет state-файлы.

Целевое состояние не передаётся во входных параметрах. EnvGene рассчитывает его по
`OPERATION_TYPE` и текущей паре состояний.

```text
OPERATION_TYPE + текущее состояние
    → проверка допустимости
    → выполнение операции
    → новое состояние
```

## Входные данные

| Параметр         | Обязательность | Описание                                        | Пример          |
|------------------|----------------|-------------------------------------------------|-----------------|
| `ENV_NAMES`      | Да             | Environment в формате `<project>/<environment>` | `sdp-dev/env-1` |
| `OPERATION_TYPE` | Да             | Тип запрошенной операции                        | `BGD-WARMUP`    |

Допустимые значения `OPERATION_TYPE`:

- `BGD-INIT`
- `BGD-WARMUP`
- `BGD-PROMOTE`
- `BGD-ROLLBACK`
- `BGD-COMMIT`

## Предусловия

1. Environment существует в Instance Repository.
2. Для Environment настроен BG Domain.
3. BG Domain содержит namespace с ролями origin и peer.
4. Оба namespace существуют в Environment.
5. Для каждой роли существует не более одного state-файла.
6. Для всех операций, кроме `BGD-INIT`, существуют state-файлы обеих сторон.
7. По state-файлам однозначно определяется текущая пара состояний.

Если предусловие не выполнено, операция завершается ошибкой. State-файлы не изменяются.

## Триггер

BG Operator инициирует операцию через BG Plugin. BG Plugin запускает Instance pipeline:

```text
ENV_NAMES: "sdp-dev/env-1"
OPERATION_TYPE: "BGD-WARMUP"
```

## Основной поток и правила выполнения операций

1. Instance pipeline получает `ENV_NAMES` и `OPERATION_TYPE`.
2. Если получена операция `BGD-*`, Instance pipeline запускает BGD-функцию EnvGene.
3. EnvGene получает BG Domain указанного Environment.
4. EnvGene определяет namespace с ролями origin и peer.
5. EnvGene читает их текущие состояния из state-файлов.
6. EnvGene сравнивает `OPERATION_TYPE` с текущей парой состояний и выбирает правило операции:

   - Если `OPERATION_TYPE` = `BGD-INIT`, допустимое текущее состояние - `ACTIVE` / `NONE`.
     EnvGene инициализирует вторую сторону и устанавливает состояние `ACTIVE` / `IDLE`.
   - Если `OPERATION_TYPE` = `BGD-WARMUP`, допустимое текущее состояние - `ACTIVE` / `IDLE`.
     EnvGene определяет `ACTIVE` namespace как источник, копирует его содержимое в `IDLE`
     namespace, сохраняет имя candidate namespace, синхронизирует `bgNsArtifacts` и
     устанавливает состояние `ACTIVE` / `CANDIDATE`.
   - Если `OPERATION_TYPE` = `BGD-WARMUP` и текущее состояние - `ACTIVE` / `FAILEDW`, EnvGene
     повторно выполняет warmup по существующему правилу retry и устанавливает состояние
     `ACTIVE` / `CANDIDATE`.
   - Если `OPERATION_TYPE` = `BGD-PROMOTE`, допустимое текущее состояние - `ACTIVE` /
     `CANDIDATE`. EnvGene устанавливает прежнему `ACTIVE` namespace состояние `LEGACY`, а
     `CANDIDATE` namespace - состояние `ACTIVE`. Новое состояние - `LEGACY` / `ACTIVE`.
   - Если `OPERATION_TYPE` = `BGD-COMMIT`, допустимое текущее состояние - `LEGACY` / `ACTIVE`.
     EnvGene устанавливает `LEGACY` namespace состояние `IDLE`. Состояние нового активного
     namespace не изменяется. Новое состояние - `IDLE` / `ACTIVE`.
   - Если `OPERATION_TYPE` = `BGD-ROLLBACK`, EnvGene проверяет текущее состояние по
     согласованному правилу rollback. Допустимое исходное и конечное состояния должны быть
     подтверждены.
   - Если значение `OPERATION_TYPE` неизвестно, EnvGene возвращает ошибку.

7. Если операция разрешена для текущей пары состояний, EnvGene выполняет действие и обновляет
   state-файлы origin и peer.
8. Если операция не разрешена, EnvGene возвращает ошибку недопустимого перехода. State-файлы не
   изменяются.
9. Instance pipeline возвращает результат BG Plugin.

Все правила, кроме первоначального `BGD-INIT`, применяются зеркально: состояние `ACTIVE` может
принадлежать как origin, так и peer. EnvGene определяет назначение namespace по текущему
состоянию, а не по постоянной роли в BG Domain.

Переключение пользовательского трафика, развёртывание, остановка и очистка workload выполняются
внешней deployment-системой.

## Таблица переходов

Состояния указаны в формате `(origin, peer)`. `NONE` означает отсутствие state-файла для
namespace до инициализации BG Domain.

Для каждого текущего состояния, кроме `(ACTIVE, NONE)`, также разрешены зеркальные переходы, в
которых состояния origin и peer меняются местами.

Пустое значение в столбце «Операция» означает, что переход существует в текущей state machine, но
код операции для нового интерфейса ещё не определён.

| Операция                         | Текущее состояние     | Следующее состояние   |
|----------------------------------|-----------------------|-----------------------|
| `BGD-INIT`                       | `(ACTIVE, NONE)`      | `(ACTIVE, IDLE)`      |
| `BGD-WARMUP`                     | `(ACTIVE, IDLE)`      | `(ACTIVE, CANDIDATE)` |
|                                  | `(ACTIVE, IDLE)`      | `(ACTIVE, FAILEDW)`   |
|                                  | `(ACTIVE, IDLE)`      | `(ACTIVE, IDLE)`      |
| `BGD-PROMOTE`                    | `(ACTIVE, CANDIDATE)` | `(LEGACY, ACTIVE)`    |
|                                  | `(ACTIVE, CANDIDATE)` | `(ACTIVE, FAILEDC)`   |
|                                  | `(ACTIVE, CANDIDATE)` | `(ACTIVE, IDLE)`      |
| `BGD-COMMIT` / `BGD-ROLLBACK`*   | `(LEGACY, ACTIVE)`    | `(IDLE, ACTIVE)`      |
|                                  | `(LEGACY, ACTIVE)`    | `(FAILEDC, ACTIVE)`   |
| `BGD-WARMUP`                     | `(ACTIVE, FAILEDW)`   | `(ACTIVE, CANDIDATE)` |
|                                  | `(ACTIVE, FAILEDW)`   | `(ACTIVE, FAILEDW)`   |
|                                  | `(ACTIVE, FAILEDC)`   | `(IDLE, ACTIVE)`      |
|                                  | `(ACTIVE, FAILEDC)`   | `(ACTIVE, FAILEDC)`   |

\* В существующем описании переход указан для commit или rollback. Необходимо подтвердить, что
`BGD-ROLLBACK` должен приводить к тому же конечному состоянию, что и `BGD-COMMIT`.

## Альтернативные потоки

### A1. Environment или BG Domain не найден

1. EnvGene возвращает ошибку.
2. Операция не выполняется.
3. State-файлы не изменяются.

### A2. Namespace не найден

1. EnvGene не находит origin, peer или соответствующий namespace в Environment.
2. EnvGene возвращает ошибку.
3. State-файлы не изменяются.

### A3. Текущее состояние не определено

1. EnvGene обнаруживает отсутствующий обязательный state-файл, несколько state-файлов для одной
   роли или неизвестную пару состояний.
2. EnvGene возвращает ошибку с описанием найденного состояния.
3. State-файлы не изменяются.

### A4. Операция запрещена для текущего состояния

1. EnvGene не находит разрешённый переход для комбинации `OPERATION_TYPE` + текущее состояние.
2. EnvGene возвращает ошибку недопустимого перехода.
3. Действие операции не выполняется.
4. State-файлы не изменяются.

### A5. Ошибка выполнения операции

1. EnvGene прекращает обработку и возвращает ошибку.
2. Instance pipeline завершается с ошибкой.
3. Правило установки `FAILEDW` или `FAILEDC` применяется только после определения соответствующих
   кодов операций и способа передачи результата внешней deployment-системы.

### A6. Ошибка обновления state-файлов

1. EnvGene возвращает ошибку.
2. Поведение при частичном обновлении определяется отдельно.

## Постусловия

### Успешное выполнение

1. Операция выполнена для разрешённого текущего состояния.
2. State-файлы содержат новое состояние origin и peer.
3. Instance pipeline возвращает успешный результат BG Plugin.

### Неуспешное выполнение

1. Instance pipeline возвращает BG Plugin ошибку с указанием причины.
2. Если изменение состояния не началось, state-файлы остаются без изменений.

## Открытые вопросы

1. Какое конечное состояние должен устанавливать `BGD-ROLLBACK`?
2. Совпадает ли переход `BGD-ROLLBACK` с переходом `BGD-COMMIT`?
3. Какие значения `OPERATION_TYPE` соответствуют переходам в `FAILEDW` и `FAILEDC`?
4. Какой `OPERATION_TYPE` используется для возврата `ACTIVE` / `CANDIDATE` → `ACTIVE` / `IDLE`?
5. Что должно происходить при повторном вызове уже выполненной операции: успешное завершение без
   изменений или ошибка?
6. Требуется ли блокировка одновременных BGD-операций для одного Environment?
