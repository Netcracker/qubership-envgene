## Description

Move actual passwords and tokens into the Secret Store using `migration-cli` (this repository,
[docs/migrate-to-external-credentials/cli](/docs/migrate-to-external-credentials/cli)) and
`external-cred-provision`. YAML cutover itself stays in
[Migrate Template Repository to External Credentials](migrate-template-repository-to-external-credentials.md)
and [Migrate Instance Repository to External Credentials](migrate-instance-repository-to-external-credentials.md).

This how-to has two parts that run at different points in the migration, not one block of work:

| Part | Command(s) | Run when |
|------|------------|----------|
| [Step 2](#step-2-collect-from-the-instance-repository) | `collect` | **Before** Instance YAML cutover - only if values still live in Instance Repository Git |
| [Step 3](#step-3-export-from-jenkins) - [Step 5](#step-5-provision-into-the-secret-store) | `export-credentials`, `fill`, `external-cred-provision` | **After** Instance YAML cutover, once the Instance pipeline has produced an External Credential Context (`EXTERNAL_CREDENTIAL_PROVISIONING=skip` run) |

Follow the exact sequencing from
[Migrate Instance Repository to External Credentials](migrate-instance-repository-to-external-credentials.md) -
this page only documents the commands, not when to run them.

Only Credentials that omit `create` (`create: false` in the plan, or a `properties`/no-`create`
entry in the final YAML) need a transferred value. `create: true` Credentials are generated by
EnvGene and never need a real password or token.

Do not commit `collect` / `export-credentials` / `fill` output files to Git. Never paste secret
values into chat, an MR description, or migration notes.

## Prerequisites

- `migration-cli` installed (Step 1)
- You know whether the passwords/tokens you need are still in Instance Repository Git or only in
  Jenkins CMDB / Cloud Deployer (this was decided per-Credential in
  [Migrate Instance Repository to External Credentials, Step
  2](migrate-instance-repository-to-external-credentials.md#step-2-decide-create-and-remoterefpath))
- One `default_store` in `configuration/secret-stores.yml`, with CI/CD auth variables configured
  for that store type
- For Jenkins export: Jenkins API credentials - `CLOUD_USERNAME` / `CLOUD_TOKEN` (default Jenkins
  host) or `JENKINS_USERNAME` / `JENKINS_TOKEN` (custom host)
- For Fernet field-level encrypted Instance Credentials: the `SECRET_KEY` environment variable

## Step 1. Install migration-cli

```bash
cd docs/migrate-to-external-credentials/cli
pip install -e .
pip install -e ".[decrypt]"   # only if Instance Credentials use Fernet field-level encryption
```

Full command reference: [cli/README.md](/docs/migrate-to-external-credentials/cli/README.md).

## Step 2. Collect from the Instance Repository

Run this **before** Instance YAML cutover, and only if actual passwords or tokens are still
committed as local Credential `data` in the Instance Repository. Skip it if all values you need
live only in Jenkins CMDB - go to [Step 3](#step-3-export-from-jenkins) instead.

```bash
export SECRET_KEY='...'   # if any field is Fernet-encrypted
migration-cli collect \
  --instance-root /path/to/instance-repo \
  --out /tmp/cred-values.yaml
```

Optional: `--env-filter cluster/env1,cluster/env2` to limit the scan.

`collect` ignores `type: external` entries - run it while Credentials are still local
(`usernamePassword` / `secret`). Once Instance YAML cutover converts an entry to `type: external`
and its `data` is removed, `collect` can no longer read that value.

Keep `/tmp/cred-values.yaml` locally until [Step 4](#step-4-fill-the-external-credential-context) -
you will not run `collect` again after cutover. Never commit it.

**Result:** a local, uncommitted values file covering every Instance-Git-sourced Credential you
will convert.

## Step 3. Export from Jenkins

Run this **after** Instance YAML cutover and after the Instance pipeline has produced an External
Credential Context (`EXTERNAL_CREDENTIAL_PROVISIONING=skip` run - see the Instance guide). Skip it
entirely if no values you need come from Jenkins CMDB / Cloud Deployer.

Default Jenkins URL (`https://jenkins.example.com`) uses `CLOUD_USERNAME` / `CLOUD_TOKEN`:

```bash
export CLOUD_USERNAME='your-user'
export CLOUD_TOKEN='your-token'

migration-cli export-credentials \
  --tenant DEMO \
  --out-dir ./cmdb-export-credentials
```

A non-default Jenkins host uses `JENKINS_USERNAME` / `JENKINS_TOKEN` (or `--username` / `--token`):

```bash
migration-cli export-credentials \
  --tenant DEMO \
  --jenkins-url https://jenkins.my-company.example \
  --username my-user \
  --token "$JENKINS_TOKEN" \
  --out-dir ./cmdb-export-credentials
```

Multiple tenants - repeat `--tenant` or comma-separate; each tenant writes its own
`{tenant}-shared-credentials.yml` into `--out-dir`:

```bash
migration-cli export-credentials \
  --tenant DEMO,ACME \
  --out-dir ./cmdb-export-credentials
```

When tenants need different Jenkins URLs or credentials, use `--config` with a multi-tenant file
instead of repeating flags:

```yaml
# export-config.yml
exports:
  - tenant: DEMO
    out_file: DEMO-shared-credentials.yml
  - tenant: ACME
    jenkins_url: https://jenkins.acme.example
    out_file: ACME-shared-credentials.yml
    username: acme-user
    token_env: JENKINS_TOKEN_ACME
```

```bash
migration-cli export-credentials --config export-config.yml --out-dir ./cmdb-export-credentials
```

Debug flags: `--dry-run` (list credential ids from CM API only, no Script Console fetch),
`--limit N` (fetch at most N credentials).

**Result:** a directory of Jenkins export files, one YAML per tenant, ready for `fill
--values-format jenkins_export`.

## Step 4. Fill the External Credential Context

Run this **after** Instance YAML cutover and after the pipeline's `skip` run has produced Context
files under `effective-set/external-credential/` for the environments you are transferring.

`fill` only writes Context entries with `strategy: fail_if_absent`. Entries with
`create_if_absent` are skipped on purpose - EnvGene / provision generates those.

From `collect` output (Step 2), whole-repository scan:

```bash
migration-cli fill \
  --repo-root /path/to/instance-repo \
  --values /tmp/cred-values.yaml \
  --values-format instance_scoped \
  --out /tmp/filled-all-environments.yaml
```

From Jenkins exports (Step 3), whole-repository scan:

```bash
migration-cli fill \
  --repo-root /path/to/instance-repo \
  --values-dir ./cmdb-export-credentials \
  --values-format jenkins_export \
  --out /tmp/filled-all-environments.yaml \
  --continue-on-error
```

With `--values-dir`, `--tenant` / `--cloud` are optional - the CLI falls back to a `*-{credId}`
suffix match across all export files when they are omitted.

Optional filters and partial runs:

```text
--env-filter cluster/env1,cluster/env2
--partial                     # write matched entries even if some fail_if_absent ids miss
--report /tmp/unmatched.yaml  # unmatched report path (default: <out>-unmatched.yaml)
```

`--partial` still exits non-zero when anything is unmatched, so provisioning is never treated as
complete by automation. Resolve the unmatched report before re-running `fill` without `--partial`.

**Result:** one flat YAML file (`/tmp/filled-all-environments.yaml`) in
[external-cred-provision](/docs/features/external-creds-provisioning-cli.md) input shape, holding
the real values matched to their Store paths.

## Step 5. Provision into the Secret Store

```bash
external-cred-provision /tmp/filled-all-environments.yaml
```

Configure store auth env vars as in the
[provisioning CLI](/docs/features/external-creds-provisioning-cli.md#environment-variables).

**Result:** secret values are written into the Secret Store. Return to
[Migrate Instance Repository to External Credentials](migrate-instance-repository-to-external-credentials.md)
to re-run the Instance pipeline with `EXTERNAL_CREDENTIAL_PROVISIONING=apply`.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| `collect` exits with an error naming a file and a required variable | Encrypted Credential found without the matching key - set `SECRET_KEY` (Fernet) or `SOPS_AGE_KEY` / `ENVGENE_AGE_PRIVATE_KEY` (SOPS, plus `sops` on PATH) |
| `fill` exits non-zero, `--partial` report lists unmatched ids | No matching value in the values file/dir for one or more `fail_if_absent` entries - re-check the source (collect output or Jenkins export) covers that environment/tenant |
| `export-credentials` needs different Jenkins URLs or auth per tenant | Use `--config` (Step 3) instead of repeated `--tenant` flags |
