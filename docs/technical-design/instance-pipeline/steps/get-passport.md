## Description

The `get_passport` step processes the Cloud Passport for an Environment Instance. The step downloads the
Cloud Passport files from the configured discovery source, validates them against the schema, writes cloud
definition fields and deploy parameters into the Environment Instance, and copies Cloud Passport
credentials into the Environment Credentials File.

## Input parameters

| Parameter      | Source   | Required | Default | Values / format             | Effect                                                                                             |
| -------------- | -------- | -------- | ------- | --------------------------- | -------------------------------------------------------------------------------------------------- |
| `GET_PASSPORT` | Pipeline | Yes      | None    | `true`, `false`             | Step runs when value is `true`. Otherwise the Instance pipeline skips this step                    |
| `ENV_NAMES`    | Pipeline | Yes      | None    | `<cluster-name>/<env-name>` | Selects the Environment Instance under `environments/<cluster-name>/<env-name>/` to process        |

## Processing flow

1. **Decide whether to run**

   The Instance pipeline runs this step when pipeline parameter `GET_PASSPORT` is `true`.

2. **Download Cloud Passport**

   The step reads the discovery configuration from `/configuration/integration.yml` (see
   [`cp_discovery` fields](/docs/envgene-configs.md#integrationyml)) and downloads the Cloud Passport
   files into the Environment Instance Cloud Passport directory. When the discovery source is a GitLab
   project, the step authenticates with the configured token and copies the files from the target
   repository.

3. **Validate Cloud Passport**

   The step validates the downloaded Cloud Passport against `schemas/cloud-passport.schema.json`.

4. **Process cloud definition**

   1. The step merges Cloud Passport deploy parameters into the Environment Instance Cloud object.

   2. The step updates `inventory.passportCloudName` in `env_definition.yml` with the Cloud name
      resolved from the Cloud Passport.

5. **Write Cloud Passport credentials**

   The step reads the Cloud Passport credentials file and copies every Credential entry into
   `environments/<cluster-name>/<env-name>/Credentials/credentials.yml`. The Credential type (local or
   external) is taken as-authored from the Cloud Passport credentials file.

   > [!NOTE]
   > In **external mode** (see [Mode detection](/docs/features/credential-processing.md#mode-detection)),
   > the Environment Credentials File is regenerated by [`env_build`](env-build.md) later in the
   > pipeline. The write performed by this step is overwritten by `env_build`'s atomic assembly in that
   > case. The step still runs, so the Credentials File reflects Cloud Passport contents even when
   > `env_build` is skipped.

## Result

1. The Environment Instance Cloud Passport directory contains the downloaded Cloud Passport files.

2. File `environments/<cluster-name>/<env-name>/Inventory/env_definition.yml` carries the resolved
   `inventory.passportCloudName`.

3. The Environment Instance Cloud object merges deploy parameters from the Cloud Passport.

4. File `environments/<cluster-name>/<env-name>/Credentials/credentials.yml` carries the Credential
   entries from the Cloud Passport credentials file. In external mode, these entries are overwritten by
   [`env_build`](env-build.md) when it runs later in the pipeline.

## Error handling

**2a.** The step fails when the discovery source is unreachable or authentication fails. The Cloud
Passport is not processed.

**3a.** The step fails when the Cloud Passport fails schema validation. The Environment Instance Cloud
Passport directory keeps the downloaded files for inspection.

**5a.** The step fails when the Cloud Passport credentials file is missing from the expected path. The
error names the expected and alternate paths searched.
