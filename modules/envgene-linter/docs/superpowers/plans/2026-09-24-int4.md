**Goal:** Report authored entities with no observed reference as Information / Review, with uncertainty explained.

**Architecture:** Catalog candidates separately from Connections. Collect typed references and analysis gaps in their
lookup contexts, then match them to candidates. INT-4 converts candidates without positive evidence into review findings.

**Tech stack:** Python 3.12, pytest, Click, and ruamel.yaml. No additional runtime dependencies.

**Spec:** [Approved INT-4 design](/modules/envgene-linter/docs/superpowers/specs/2026-09-24-int4-design.md).

All paths below are relative to `modules/envgene-linter` unless they start with `/`.
The user approved this plan and inline execution on September 24, 2026.

## Global constraints

- Automatic deletion is outside the scope of this rule.
- There is no Warning / Fix mode for supposedly confirmed unused entities.
- Generated objects can provide evidence of a reference, but they are not cleanup candidates.
- The first version does not inventory entities inside template repositories.
- Do not recursively interpret secret values inside Credential catalogs as reference expressions.
- Never include Credential IDs, secret values, source expressions, or raw parser exceptions in finding text or skip notes.
- Enable INT-4 by default after INT-3. Disabling it must bypass its additional candidate and reference analysis.
- Keep the generator and other rules' observable behavior unchanged.

Run locally without template fetching, rendering, or decryption. Preserve the existing nonfatal findings exit code.
Use repository-contained paths outside `.git` and do not traverse directory symlinks.
Preserve the existing uncommitted INT-3 work. Do not stage unrelated changes or bypass the secret-scanning hook.

## Review focus

- Cyclic YAML aliases must terminate without interpreting a Credential payload as executable reference syntax. Task 2.
- Invalid UTF-8 and non-mapping YAML must produce generic skips or scoped gaps without leaking parser contents. Task 1.
- A file alias across scopes must retain all applicable contexts but produce only one cleanup finding. Tasks 1 and 3.
- An unbound generated namespace can still consume an authored entity. Task 2.
- Case-insensitive filesystems must not duplicate catalogs discovered through `credentials` and `Credentials`. Task 1.

## File responsibilities and interfaces

Create `src/envgene_linter/usage_model.py` for records, `usage_candidates.py` for authored discovery,
`usage_references.py` for consumer discovery and matching, and `rules/int4.py` for finding construction.
Keep source-selection helpers private to these modules unless their contract below is public.
Do not add unconnected paths to Connections or import private INT-2 checker methods.

Define these records in `usage_model.py`. Candidate names and Credential IDs are internal and must never reach reports.
An environment context is `EnvModel.full_name`. An empty environment tuple means no known consuming environment.

```python
from dataclasses import dataclass
from pathlib import Path
from typing import Literal

Kind = Literal["ParameterSet", "Shared Template Variable", "Resource Profile Override", "Credential"]

@dataclass(frozen=True)
class Candidate:
    path: Path
    physical: Path
    kind: Kind
    name: str
    environments: tuple[str, ...]
    aliases: tuple[Path, ...] = ()
    line: int = 1
    column: int = 1

@dataclass(frozen=True)
class Reference:
    source: Path
    kind: Kind
    name: str
    environment: str | None
    catalog: Path | None = None
    category: str | None = None
    target: str | None = None

@dataclass(frozen=True)
class Gap:
    source: Path
    kind: Kind
    environment: str | None
    reason: str

@dataclass(frozen=True)
class Usage:
    candidate: Candidate
    references: tuple[Reference, ...]
    gaps: tuple[Gap, ...]
```

Use fixed reason codes: `dynamic`, `unreadable`, `no-environment`, `provenance`, and `lookup`.
The report always adds the external/rendered-consumer limitation, independently of these codes.
Retain category and target when matching ParameterSets. A missing context is uncertainty, not a global match.
