## Purpose and scope

[VAL-4](/docs/configuration-standard.md#val-4---complex-values-are-native-yaml-should) recommends native YAML maps
and lists instead of serialized structures inside strings. This first version checks connected ParameterSets only.

Inspect `parameters` and `applications[].parameters` for every selected physical ParameterSet across deploy,
end-to-end, and technical categories. Walk nested maps and lists. Report source values before effective-value merging.
The existing Connections resolver determines selection, including staging and shadowing.

Cloud Passports, Shared Template Variables, Resource Profile Overrides, Credential catalogs, generated Cloud/Namespace
objects, metadata fields, unused files, and unresolved references are outside this version's scope.
Jinja files, unreadable inputs, and paths outside the repository or inside `.git` are excluded.

## Recognition contract

- A string containing one complete JSON object or array is a candidate, including empty objects and arrays.
  JSON primitives, trailing text, invalid JSON, and nonstandard constants such as `NaN` are excluded.
- A YAML literal or folded block scalar (`|` or `>`) is a candidate if its decoded content parses as one map or list.
  Scalar results, multiple documents, malformed content, explicit tags, anchors, and aliases are excluded.
- Ordinary quoted strings are not parsed as general YAML. In particular, `Note: restart required` remains ordinary text.
  Quoted YAML flow syntax that is not valid JSON is outside this version's recognition contract.
- Values containing `${`, `{{`, `{%`, or `{#` are skipped because their rendered structure is unknown.
- Native maps and lists are valid containers. Their nested string values are still checked.
- Recognition never evaluates templates, expands macros, loads external data, or writes converted values.

Candidate strings are limited to 65,536 characters and 64 nested collections.
YAML block parsing additionally limits the token stream to 4,096 tokens.
Limit hits produce a generic file-level skip note. The outer document walker stops cycles and limits nesting to 64 levels.
Each parameter bag allows 65,536 node visits before its remaining traversal is skipped.
These safeguards apply inside VAL-4, after common discovery and effective-set computation.

## Findings

Emit one Warning / Review finding per physical file and YAML value path, even if several environments use the file.
Use the existing YAML key/item location and expose the parameter path as `key`.
The message identifies the encoded format and collection kind without copying the string or decoded contents.
The hint recommends native YAML only after confirming that the consumer accepts a map or list.
A block containing ordinary configuration text can still parse as a collection, so a finding requires human review.

Keep console severity and exit code 0 for findings. HTML shows Action Review without a Type row.
Enable VAL-4 by default after NAME-8. Disabling it bypasses parsing and removes its findings and skip notes.

## Implementation design

Add `rules/val4.py` with the existing `check(index, connections=None)` interface.
Reuse loaded ParameterSets, Connections, path safety checks, source positions, and finding metadata.
Use the standard-library JSON decoder and the existing `ruamel.yaml` dependency. No formatter or new dependency is needed.

Separate bounded string recognition from the iterative traversal of parameter bags.
Inspect the YAML token stream before composing a block scalar, rejecting unsupported constructs and excessive nesting.
Composition recognizes map/list nodes without constructing tagged objects or applying merge keys.
Validate depth in the composed tree too, because scanner tokens omit indentless sequence starts.
Track container ancestors during the outer walk so aliases at different value paths remain visible while cycles terminate.
Sort findings by path, line, column, and key. Deduplicate limit notes by file.

## Acceptance criteria

Tests cover JSON maps/lists, empty collections, literal and folded YAML blocks, native structures, nested/app values,
source positions, all categories, shared files, unused and shadowed inputs, malformed and scalar strings, dynamic content,
unsupported tags/aliases, size/depth limits, cyclic native containers, unsafe paths, and disabled-rule behavior.
CLI and HTML tests verify Review, exit code 0, deterministic output, and absence of encoded contents.
Runnable positive and negative examples exercise the public engine.

The current processing flow is documented in [the algorithm](/modules/envgene-linter/docs/algorithms/val4.md).
