# SEC-1: literal secrets in connected parameters

Status: implemented; this specification retrospectively records the agreed intent and the current implementation choices.

## Requirement and interpretation

Secrets must not be stored as literal parameter values, for example `DB_PASSWORD: example-only`. Use a Credential reference instead. The user confirmed this interpretation and the requirement to keep repository data local.

The implementation detects candidates by parameter name. This is a heuristic implementation choice, not proof that a value is a secret and not complete detection of all secrets.

## Scope

Apply the common connected-only scope. Inspect selected ParameterSets, both `parameters` and `applications[].parameters`, recursively through mappings and lists.

Also inspect `deployParameters`, `e2eParameters` and `technicalConfigurationParameters` in each discovered environment's `cloud.yml` and selected `Namespaces/<target>/namespace.yml`. A Namespace target is selected through a resolved ParameterSet use or resource-profile binding; mere file existence is insufficient. Do not infer further use from unavailable templates.

Require local existing files inside the repository and outside `.git`, including resolved symbolic-link targets. Skip unreadable, malformed or non-mapping object documents and unloaded or Jinja ParameterSets. Protect recursive traversal against cyclic YAML aliases. Inspect each selected physical object file once.

## Detection contract

1. For each scalar leaf, use the last string component of its parameter path as its name. A list index does not replace the enclosing name.
2. Recognize terminal tokens `password`, `passwd`, `pass`, `secret`, `token`, `private_key` and `api_key`. The token must start the name or follow `_`, `.` or `-`. Match case-insensitively and also normalize camelCase and acronym boundaries to snake_case.
3. Skip null and empty-string values. Skip complete mappings marked `$type: credRef`. Skip strings containing `${`, `{{` or `{%`; expressions are not evaluated, and skipping does not establish safety.
4. Report other literal leaves whose name matches, including numbers and booleans. Placeholder-looking or encrypted-looking strings receive no special exemption.

Examples: `DB_PASSWORD`, `db.password`, `apiKey` and `APIKey` match; `PASSWORD_LENGTH`, `TOKEN_TTL`, `token.path` and `credentialsId` do not. A secret under an unrelated name can be missed.

## Findings and boundaries

Emit **Warning / Fix** at the parameter's YAML position, with its full key and scope. State that the name looks secret-related and the value is literal; suggest storing it in a Credential and referencing it. Do not include the value or parser exception text. Sort by path, key and line.

No value-strength tests, entropy analysis, Credential resolution, expression evaluation, automatic rewrites or network access are part of this rule. Existing CLI exit behavior remains unchanged. Other rules may independently report the same parameter.

## Verification

Synthetic fixtures must cover matching and non-matching names, case normalization, nested mappings and lists, application parameters, all three object sections, connected versus unused inputs, expressions, structured references, empty values, scalar types, cyclic aliases and safe-path boundaries. Verify locations, deterministic reporting and absence of tested secret values from findings and report output. See the linked tests for executable cases.
