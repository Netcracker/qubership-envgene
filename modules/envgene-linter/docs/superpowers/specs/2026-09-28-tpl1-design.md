## Purpose and repository types

[TPL-1](/docs/configuration-standard.md#tpl-1---jinja-lives-only-in-j2-templates-must) checks Jinja in plain YAML
in both template and instance repositories. A repository root contains `templates/`, `environments/`, or both.
The absence of `environments/` is normal for a template repository.

On a template-only repository, run TPL-1 and mark instance-only rules Not applicable in console and HTML reports.
On a mixed repository, retain existing instance checks and run TPL-1 across both trees.
Reports omit rules disabled at build time, including their Not applicable status. No new command or flag is required.

## File scope

Recursively inspect `.yml`, `.yaml`, and `.j2` files under `templates/`, `environments/`, and `configuration/`.
TPL-1 checks file syntax independently of bindings, including unused and shadowed YAML files.
This exception does not expand the input sets of other rules.

A `.j2` file is allowed regardless of its directory. TPL-1 does not check template file placement.
Plain YAML is inspected as source text even if YAML parsing fails. YAML comments are excluded.
No template evaluation, network lookup, file conversion, or automatic rename occurs.

Exclude other roots, including CI, samples, and root build-description files. Do not traverse directory symlinks,
`.git`, `.venv`, `node_modules`, or `__pycache__`. Reject unsafe file links outside the repository or inside `.git`.
Deduplicate findings by physical file and line. Inspect logical aliases independently because only some paths
can qualify for descriptor exceptions. Read each physical YAML file once.

## Descriptor exceptions

The user approved generator-supported Jinja fields in ordinary YAML descriptors as an exception to the extension rule.
Use [the descriptor schema](/schemas/template-descriptor.schema.json),
[descriptor composition](/docs/features/template-composition.md), and
[the generator](/scripts/build_env/render_config_env.py) as the field contract.

Recognize descriptors under `templates/env_templates/` by a mapping with `tenant`, `cloud`, and a `namespaces` list.
Composed descriptors with a `parent-templates` mapping may inherit tenant and cloud.
A mapping-valued tenant can select a parent. Do not require the final rendered descriptor schema before composition.

Exempt source scalars in these fields:

- `tenant`, scalar `cloud`, `composite_structure`, `bg_domain`, and `external_credential_template`.
- `cloud.template_path` and scalar keys and values within `cloud.template_override`.
- `namespaces[].template_path` and scalar keys and values within `namespaces[].template_override`.
- `name` and the direct `deployParameters`, `e2eParameters`, and `technicalConfigurationParameters` maps
  in `overrides-parent` for cloud or namespace entries with a parent in a composed descriptor.
  A namespace without `template_path` may infer its parent when exactly one parent template is declared.

The generator renders these values or objects separately, including composition overrides merged into `template_override`.
Also allow `namespaces[].name` as schema-documented selector syntax. This field is an exact composition selector,
not a generator-rendered expression. Other fields and standalone Jinja statements
remain checked. Other composition parent selectors and parameter-set lookup lists do not receive a blanket exemption.
Path fields must be scalars and override bags must be mappings to qualify.
Use YAML source marks so an allowed value does not exempt another expression on the same line.
An alias referring to an anchor outside the allowed field does not exempt that anchor's source.
If the descriptor cannot be composed, apply no field exemptions.

## Recognition and findings

Scan complete `{{ ... }}`, `{% ... %}`, and `{# ... #}` delimiter pairs in source order.
Support multiline and whitespace-control forms, and suppress nested openings inside a complete outer construct.
Isolated delimiters and EnvGene `${...}` macros alone are silent. Ignore YAML comments before matching delimiter pairs.
Keep hashes inside quoted strings and block scalar content eligible. An unclosed delimiter in a YAML comment
must not consume an expression on a later active line.

Use Warning / Fix for Jinja statement/comment delimiters and expressions referring to recognized
EnvGene context names outside quoted literals. Context names include `current_env`, `templates_dir`, `templates_dirs`,
`current_env_template`, `peer_env_template`, `origin_env_template`, `env_definition`, `cloud_passport`, `env_vars`,
and `namespace_by_deploy_postfix`.

Use Information / Review when shared expression delimiters do not establish the renderer.
Helm or application syntax containing `$`, `===`, `!==`, `=>`, `&&`, or `||` outside quoted literals remains Review,
even if it mentions an EnvGene context name. This is conservative lexical recognition, not full Jinja validation.
Review findings explicitly allow retaining syntax required by a downstream consumer.

Keep one finding per physical file and source line. Fix takes precedence over Review on the same line.
Point to the first occurrence in the chosen category. Never copy source contents or keys into findings.
Internal classification is Error for Fix and Information for Review. HTML continues to omit Type.
Findings retain exit code 0. Read failures produce generic skip notes without exception contents.

## Implementation design

Accept either repository root in discovery. Route template-only checks before instance resolution and effective sets.
Pass rule applicability to console and HTML rendering so unexecuted rules do not appear to have passed.

TPL-1 walks its own roots and reuses path safety checks. Parse descriptor nodes without constructing custom objects
only to obtain exemption spans. Use monotonically advancing delimiter searches and a newline index for source positions.
Compose safe YAML nodes to validate syntax without constructing objects. Use YAML scanner tokens to locate comments.
Determine comment ends from source line boundaries, never from normalized token value lengths.
Handle block scalar header comments separately. Mask comments with spaces without changing newlines or offsets.
If YAML composition or scanning fails, use a lexical pass that tracks quotes, block scalar indentation,
flow collections, scalar properties, plain continuation lines, and document markers.
Keep complete Jinja constructs opaque within the current YAML quoted scalar boundary.
A delimiter family with no closing token remaining is disabled for the rest of that file's scan.
No new dependency is required.

TPL-1 is enabled after VAL-4 by default. Disabling it prevents TPL-1 traversal, parsing, and skip notes.
Instance discovery can still emit its own diagnostics independently.

## Acceptance criteria

Tests cover template-only and mixed repositories, all supported roots, unused files, directory-independent `.j2` handling,
descriptor fields, composition, field-specific source spans, aliases, malformed YAML, and unsupported directories.
Recognition tests cover all delimiters, multiline content, keys, YAML comment exclusion, scalar hashes,
redaction, macros, ambiguous syntax, source positions, duplicate paths, unsafe links, disabled behavior,
CLI exit codes, and report applicability.

Maintain English documentation, runnable examples, and a functional changelog entry.
Validate local template repositories without modifying their files. Publish ticket updates only after a commit.
See [the algorithm](/modules/envgene-linter/docs/algorithms/tpl1.md) for the processing sequence.
