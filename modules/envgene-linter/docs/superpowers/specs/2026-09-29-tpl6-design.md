## Purpose and scope

[TPL-6](/docs/configuration-standard.md#tpl-6---keep-template-logic-small-should)
checks template logic that should be expressed through values or template composition.
It shares the source selection and read-only parser described in
[the TPL-4 design](/modules/envgene-linter/docs/superpowers/specs/2026-09-29-tpl4-design.md#purpose-and-scope).
No instance bindings or `environments/` directory are required.

## Construct classification

Report `macro`, `include`, `import`, `from ... import`, `extends`, and `block` as Warning / Fix.
Report filters absent from Jinja's built-in filter set as Warning / Fix, including generator-specific custom filters.
Support in the generator does not make a custom filter compliant with TPL-6.

Allow `if`, `elif`, `else`, `default`, `join`, `upper`, and `lower`.
Treat `d` as the Jinja alias of `default`.
Other built-in filters and statements such as `set`, `call`, `with`, and filter blocks produce Information / Review.
The standard names an allowed subset without explicitly forbidding every other built-in construct.

Report a `for` over a literal container or a literal `range(...)` as Warning / Fix.
A variable-based iterable is accepted as a potentially dynamic input. Its runtime type and size are not proven.
Recursive loops produce Information / Review.
The first version does not follow assignments to prove that a variable-based iterable is constant.
It does not impose a nesting threshold because the standard does not define one.

## Helm passthrough

TPL-8 requires `raw` for Helm, although TPL-6 lists `raw` as forbidden.
The agreed interpretation allows recognizable Helm passthrough and reports other raw blocks as Information / Review.
The rule never recommends removing a raw block automatically.

A recognized block contains Helm expressions using standard context roots such as `.Values` or `.Release`,
or a Helm `include` call with a quoted name and a `.` or `$` context argument.
A function name alone does not establish Helm syntax. A `tpl` expression needs recognizable context evidence. Helm flow-control tokens and local `$` variables are accepted with this evidence.
Every expression in the block must match this limited recognition. Mixed or ambiguous expressions produce Review.
Plain text without recognizable Helm expressions also produces Review.
This is a syntax heuristic, not a Helm validator or an implementation of TPL-8.
Jinja inside a raw block is never analyzed as executable EnvGene logic.

## Findings and implementation

Use the existing Finding model and report headings. Keep one finding per physical file, line, and construct category.
Positions identify the opening source line with column 1.
Descriptor findings identify the start of the selected YAML scalar. Messages omit source values and custom identifiers.
Fix hints suggest template composition or explicit values. Review hints state the uncertainty.
Do not evaluate expressions, load includes, contact other repositories, or modify inputs.

Use the shared Jinja abstract syntax tree for statements and filters.
Use lexer tokens for raw blocks because the parser turns their contents into plain template text.
Syntax and read failures produce generic skip notes, and other eligible files remain checkable.
The rule is enabled by default and independently switchable. Disabled rules remain absent from reports.

Tests cover every prohibited construct, approved filters, other built-in filters, custom filters,
literal and dynamic loops, raw recognition, comments, malformed templates, safe paths, and report integration.
Runnable fixtures demonstrate compliant and noncompliant template fragments.
See [the algorithm](/modules/envgene-linter/docs/algorithms/tpl6.md) for the traversal sequence.
