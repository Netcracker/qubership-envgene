## Purpose and scope

[TPL-6](/docs/configuration-standard.md#tpl-6---keep-template-logic-small-should)
checks template logic that should be expressed through values or template composition.
It shares the source selection and read-only parser described in
[the TPL-4 design](/modules/envgene-linter/docs/superpowers/specs/2026-09-29-tpl4-design.md#purpose-and-scope).
No instance bindings or `environments/` directory are required.
An additional [compatibility pass](/modules/envgene-linter/docs/algorithms/ansible-compatibility.md) checks legacy
expressions in configuration YAML, including instance repositories. Root GSF/CI description templates are excluded.

## Construct classification

Report `macro`, `include`, `import`, `from ... import`, `extends`, and `block` as Warning / Fix.
These are Jinja statements, not filter names.

Allow all built-in and custom filters without an allowlist, including generator-specific filters and dotted names.
Filter chains and `{% filter ... %}` blocks are allowed. Statements inside filter blocks remain eligible for checks.
The compatibility pass reviews filters absent from the applicable renderer and statically unsupported arguments.
Unknown rendering stages also receive Review when support cannot be confirmed. No filter is executed.

Allow `if`, `elif`, and `else`. Statements such as `set`, `call`, and `with` produce Information / Review.
Allowing filters does not exempt assignments, literal loops, or other surrounding statements.

Report a `for` over a literal container or a literal `range(...)` as Warning / Fix.
A variable-based iterable is accepted as a potentially dynamic input. Its runtime type and size are not proven.
Recursive loops produce Information / Review.
The first version does not follow assignments to prove that a variable-based iterable is constant.
It does not impose a nesting threshold because the standard does not define one.

## Raw passthrough

TPL-8 requires `raw` for Helm, although TPL-6 lists `raw` as forbidden.
The approved interpretation allows all syntactically valid raw blocks without a style prohibition.
This includes Helm, application placeholders, mixed syntax, plain text, and empty blocks.
The rule does not require evidence of a particular downstream consumer.

Raw contents are literal template text, so statements and filters inside the block are not executable Jinja inputs
to TPL-4 or TPL-6. Statements outside raw blocks remain eligible for TPL-6.
TPL-4 still checks presence protection for input references, including references used with filters.
The surrounding template must still parse. An unclosed raw block produces a generic incomplete-check diagnostic.
Allowing raw does not validate its downstream syntax or implement TPL-8.
Compatibility Review identifies known EnvGene transformations that change literal raw content before Jinja processing.

## Findings and implementation

Use the existing Finding model and report headings. Keep one finding per physical file, line, and construct category.
Positions identify the opening source line with column 1.
Descriptor findings identify the start of the selected YAML scalar. Messages omit source values and custom identifiers.
Fix hints suggest template composition or explicit values. Review hints state the uncertainty.
Do not evaluate expressions, load includes, contact other repositories, or modify inputs.

Use the shared Jinja abstract syntax tree for statements and filters.
The parser represents raw contents as plain text, so the checker needs no separate raw-content classification.
Syntax and read failures produce generic skip notes, and other eligible files remain checkable.
The rule is enabled by default and independently switchable. Disabled rules remain absent from reports.

Tests cover every prohibited construct, built-in and custom filters, filter blocks,
literal and dynamic loops, unrestricted raw passthrough, comments, malformed templates, safe paths, and report integration.
Compatibility tests also cover supported transformations, unavailable filters, argument contracts, rendering stages,
and literal-content changes.
Runnable fixtures demonstrate compliant and noncompliant template fragments.
See [the algorithm](/modules/envgene-linter/docs/algorithms/tpl6.md) for the traversal sequence.
