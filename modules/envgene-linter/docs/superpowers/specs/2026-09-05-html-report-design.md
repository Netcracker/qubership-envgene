## Goal

`envgene-linter check <repo> --html` still prints the console report, and also writes a self-contained HTML page of the same findings, grouped by file.

Without `--html`, behaviour is unchanged: console only.

## In plain terms

The console is for terminals and CI logs. The HTML file is for opening in a browser: one heading per file that has findings, cards under it with the rule and the text. A finding is one reported issue (`Finding`), which may concern one or more source files.

No autofix. No suggested YAML. No JSON. Skipped Jinja / unreadable YAML stay on stderr, not in the page.

## Out of scope (this cycle)

- Autofix / suggested edits
- JSON report, `--strict`, `--rules`, baseline, `[EXCEPTION …]`
- Editing the instance repo `.gitignore`
- Changing file discovery, the Effective Set (parameter values after layer merging), or PLACE-1/2/3
- Changing the console renderer

## CLI

```text
envgene-linter check <repo> --html
```

`--html` is a flag (no path argument). The file is always:

```text
<instance-repo-root>/envgene-linter-report.html
```

The instance-repo root is the directory that contains `environments/` (the same root `check` already takes). The file is overwritten each `--html` run.

After a successful write, print one line on **stderr**:

```text
Wrote HTML report to envgene-linter-report.html
```

The original design allowed a relative or absolute path in this notice. The redesign fixes the notice to the exact text shown above.

Console findings stay on **stdout**, same bytes as without the flag (plus the usual skipped notes on stderr).

## Write failure

If `--html` is set and the file cannot be written:

1. Console findings have already been printed (or print them first, then attempt the write).
2. Error on stderr, e.g. `cannot write HTML report <path>: <reason>`.
3. Exit **2**.

Without `--html`, exit codes stay: `0` on warnings / no findings, `2` if there is no `environments/` or on bad CLI usage.

## Page

One HTML document. Inline CSS. No JavaScript. No `<script>` tags. `lang="en"`. Escape every finding field and every path (`html.escape`) so a `<` in a message cannot become markup.

### Header

- Title: `envgene-linter report`
- One muted summary line: finding counts per rule in `RULE_ORDER` (`PLACE-1`, `PLACE-2`, `PLACE-3`), e.g. `PLACE-1: 1, PLACE-2: 0, PLACE-3: 2`
- Note: generated by `envgene-linter check --html`; do not commit this file; it is overwritten every run

### Body

Only files that have at least one finding.

1. Sort files by their path relative to the instance-repo root (POSIX-style `/` separators).
2. One heading per file (relative path, monospace).
3. Under the heading, that file's findings as cards, in console rule order (`PLACE-1`, then `PLACE-2`, then `PLACE-3`). Same rule: keep engine order.

Each card shows:

| Field | Source |
| --- | --- |
| rule | `Finding.rule` |
| severity | `Finding.severity` (`warning`) |
| line | `Finding.line` |
| message | `Finding.message` |
| hint | `Finding.hint` |

Do not print `scope` or `related` (console does not either).

Zero findings: still write the file. Header + summary of zeros + a single `No findings` (no file headings).

### Card (meaning, not pixels)

```
<relative/path.yml>

  PLACE-3 · warning · line 4
  <message>
  <hint>
```

Left border or similar so a card is visibly a card. Light theme, system font, readable without extra assets.

## Code changes

| File | Role |
| --- | --- |
| `src/envgene_linter/html_report.py` | `REPORT_FILENAME`, `report_path(root)`, `render_html(findings, root)` |
| `src/envgene_linter/cli.py` | `--html`; write after console render |
| `tests/test_html_report.py` | Page content |
| `tests/test_cli.py` | Flag writes / omits the file; write failure |

`report.py` stays the console renderer. `engine.py` stays as it is (`CheckResult.findings` + `skipped`).

`render_html` takes the finding list and the repo root (for relative paths). It does not need suggestion plans.

## Tests

Add renderer and CLI tests for this stage:

- `--html` creates `envgene-linter-report.html` at the repo root; without the flag no file is created (an existing report is left untouched)
- Two findings in one file → one file heading, two cards
- Findings in two files → two headings
- Zero findings → file exists, contains `No findings`, no file heading
- A `<` in `message` appears as `&lt;`, not as a tag
- Rendered HTML contains no `<script`
- With `--html`, stdout is the same console report as without it
- Unwritable target → stderr mentions the path, exit 2 (after stdout has the console report)

Do not add PLACE-* lab trees for this cycle.
