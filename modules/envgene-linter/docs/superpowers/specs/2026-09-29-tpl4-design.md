## Purpose and scope

[TPL-4](/docs/configuration-standard.md#tpl-4---a-reference-never-fails-on-a-missing-value-should)
asks template authors to protect references to potentially absent inputs.
The rule checks `.j2` files under `templates/` and generator-rendered fields in recognized environment template descriptors.
It runs in template-only and mixed repositories without requiring instance bindings.
Instance-only repositories have no eligible template sources. TPL-1 handles misplaced Jinja separately.

Descriptor selection follows [TPL-1](/modules/envgene-linter/docs/algorithms/tpl1.md), excluding
`namespaces[].name`, which is a selector rather than a generator-rendered field.
Each selected YAML scalar is decoded and analyzed independently. File traversal preserves TPL-1 path safety restrictions.
Ordinary YAML, files outside `templates/`, and Jinja comments are outside this rule's scope.

## Presence protection

The rule accepts `default` and its Jinja alias `d` directly around a reference.
One trailing default protects an entire attribute or item path, as described by TPL-5.
Fallback arguments and dynamic item indices are checked independently.
A default after arithmetic, a call, or another filter does not protect that operation's inputs.

An `is defined` or `is undefined` test of a reference needs no default.
The test protects reads of that exact path in branches where the path is known to exist.
Boolean short-circuit evaluation and conditional expressions preserve this protection.
A test of a parent object does not establish the presence of every child.

Loop targets and assigned local names are bound within their scopes. Their optional attributes still require review.
Jinja globals and standard loop properties are recognized. Local bindings take precedence over generator names.

In `.yml.j2` and `.yaml.j2` sources, recognize the generator's replacement of standalone
`lookup('ansible.builtin.env', 'NAME')` with `env_vars.NAME` before evaluating presence protection.
The generator pattern requires single-quoted literal arguments and no space between `lookup` and `(`.
Whitespace inside the parentheses is allowed. A direct default or appropriate presence guard protects this reference.
An unguarded lookup, another function, or an unsupported call form remains a review candidate.
Do not apply this replacement to ordinary descriptor scalars or bare `.j2` ParameterSet templates.

## Generator context

All eligible sources recognize `current_env`, `current_env.name`, and `current_env.environmentName`.
Recognized ordinary YAML descriptor scalars also receive `templates_dir` and these paths from `setup_base_context`:

- `current_env.cloud` and `current_env.cloudNameWithCluster`.
- `current_env.description`, `current_env.owners`, and `current_env.env_template`.
- `current_env.envSpecificParamsets` and `current_env.additionalTemplateVariables`.
- `current_env.cluster` and its `cloud_api_protocol`, `cloud_api_url`, `cloud_api_port`, and `cloud_public_url` fields.
- `current_env.cloud_passport` and `current_env.solution_structure`.

These guarantees cover presence, not type or dictionary contents. `current_env.tenant`, `current_env.deployer`,
and arbitrary children remain optional. Do not extend the descriptor guarantees to full `.j2` sources:
their rendering stages and fallback contexts differ. Local rebinding invalidates the corresponding guarantees.
The context contract follows
[environment configuration](/scripts/build_env/templates/env_config.yml.j2) and
[descriptor rendering](/scripts/build_env/render_config_env.py).

## Findings and limitations

Every finding uses Information / Review. A finding means the source lacks recognized presence protection.
It does not prove that the input is absent or that generation fails.
EnvGene uses `ChainableUndefined`, so missing values do not fail in every expression.
The standard's unguarded equality example remains a review candidate even though that comparison can render successfully.

Report one candidate per physical file and source line, with column 1.
Descriptor findings point to the start of the selected YAML scalar because quoting and folding can change line counts.
Messages and hints do not copy variable names, expressions, literal values, or parser exception text.
Hints ask the author to verify the input contract and use appropriate protection without inventing a business default.
No source rewrite or template execution occurs. Findings retain the CLI's existing exit code behavior.

The rule does not resolve external template inputs, execute filters, prove types, or infer arbitrary data flow.
Unrecognized protection can produce a review candidate. Syntax, read, and analysis recursion failures produce
generic skip diagnostics with locations, following the [report contract](/modules/envgene-linter/docs/algorithms/reports.md).

## Implementation and verification

Use Jinja2 3.1.6, matching the generator, to build an abstract syntax tree without rendering or compiling a template.
A shared source reader parses eligible sources once per check and supplies both TPL-4 and TPL-6.
TPL-4 can parse a separate representation with the supported lookup replacement. Preserve original line numbers
and retain the original source tree for TPL-6. Never execute lookup functions or templates.
Each rule remains independently switchable. Disabling both prevents shared traversal and parsing.
Add both rules to the existing metadata, build-time switches, report order, and template repository dispatch.

Tests cover missing inputs, defaults, evaluation order, presence guards, nested paths, local scopes,
descriptor fields, template-only repositories, invalid syntax, source positions, redaction, and disabled rules.
Provide runnable positive and negative fixtures and keep development documentation out of distribution archives.
See [the algorithm](/modules/envgene-linter/docs/algorithms/tpl4.md) for processing details.
